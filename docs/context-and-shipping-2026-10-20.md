# 模型上下文、并行读取与运输规则选择

本次采用同一个业务 Agent。模型仍须自己读取 Ontology、选择动作与依赖、检查事实和关卡并明确完成；没有加入 Multi-Agent，也没有把交易流程写成固定步骤。

## 上下文与执行

- 模型只接收历史计划摘要、已执行动作的状态、观察引用和反馈。完整计划、读取回执、签名与版本保留在持久账本，执行前照常校验。
- 业务模型内部的 `describe_ontology` 接口默认给出简明动作目录；通过 `actions=[准确动作名称]` 读取所需输入 Schema。`includeSchemas=true` 仍可获取完整定义。跨领域条件 Schema 通过 `includeConditionSchema=true` 按需读取，避免每次解释请求都注入全部合同。解释阶段只选择能力和整理要求，业务范围在解析成功后初始化；模型的解释决策也保存到任务账本。
- 单次模型读请求可容纳最多 8 项 Ontology 操作，总读取预算仍为 20。它们按列出顺序执行，可先查询已知引用，再在同批求值。外部来源查询在动作计划中调度。
- 同一个只读计划最多 4 个动作：独立动作并发，依赖动作在自己的前置动作确认后启动。一个慢分支不会阻挡另一条已经具备输入的链路。
- 包含业务写入的计划继续串行，并保留准确计划授权。查询失败只阻断依赖它的后续动作；取消或租约失效的迟到结果仅进入审计，不能推进任务。中断的请求不会自动重放。

## 运输规则

规则由实际库存与运输事实决定：每个包裹的仓库、库存监管状态、放行依据、逐段起终点和关境、目的地、数量及完整路线摘要必须一致。商家注册地、商品原产地与发货地分别保存，不能相互替代。

| 有证据支持的路线 | 选择的检查 |
|---|---|
| 本地已放行、可流通库存，本地运输 | 国内商品承运与承运方接受条件；进口检查标为不适用 |
| 同一关境内的跨地区运输 | 地区运输规则与商品承运条件 |
| 实际运输段跨关境 | 海关准入与运输条件 |
| 本地保税或仍受海关监管的库存 | 保留海关手续检查，不能因仓库在本地跳过 |
| 多包裹使用不同监管路径 | 分包裹判断，汇总所有适用条件 |
| 关境、库存状态、放行依据或路线缺失／冲突 | `unknown`，阻止报价、结账和下单推进 |

新增 `shippingGateStatus`。原 `customsGateStatus` 是兼容入口，返回相同的路线分类和适用检查；二者均不能赋予执行权限。`ReadCommerceCustoms` 沿用已有动作名称，返回所选路线的运输／海关来源评估。模型必须实际读取当前规则及参考文献并求值；PA 许可不能覆盖未知或失败结果。

国内运输仍有禁限寄及特定商品运输要求，参见 [快递暂行条例（2025 年修订）](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_ccea5d29862840979d0ff2304edabbb2.html)。综合保税区与境内区外之间的货物流动仍有相关海关手续，参见 [海关综合保税区管理办法（2024 年修正）](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=101346)。两份官方正文均保留获取时间及内容摘要，加入原有参考文献目录。

当前可执行规则和关境映射仅覆盖明确登记的合成测试。它们验证如何选择与执行关卡，不构成完整的国内、区域或全球法规服务，也不证明真实库存已经放行。所有结果保留 `legalApproval=false`。本次没有真实下单、付款或联系承运商。

## 验证与性能对比

代码验证覆盖依赖并发、分支失败、取消、租约失效、证据保留、国内已放行／保税库存、跨境转运、区域运输和未知承运条件。既有海关硬关卡和授权绕过测试继续保留。

性能比较使用上一轮相同的只读咖啡报价请求，原始输入不变；来源与模型传输配置保持一致。新增运输字段及两份参考文献会增加本轮必须处理的事实。记录任务总耗时、模型调用次数、输入／输出 token 和缓存输入量；模型服务耗时有波动，单次样本不能证明普遍的速度提升。完成后的实际结果与独立回读归档在本页关联的证据目录。


实际成功路径：**356.537 → 319.861 秒**（减少 10.29%）；**26 → 19 次模型调用**（减少 26.92%）；**1,467,996 → 814,805 输入＋输出 token**（减少 44.50%）。报价仍为 270.00 CNY，实际观察到两路来源请求并发。Ontology 读取从 52 增至 59，必要规则检查没有被省略。

399 项测试与 7 项跨进程测试通过。独立回读核对了终态、模型决策、来源签名、关卡重算和零业务写入。调试期间的两次初始化失败及其 391,199 token 也完整保留；它们未产生来源查询或业务动作。单样本、缓存及模型版本限制详见[证据与完整对比](evidence/context-and-shipping-2026-10-20/README.md)。
