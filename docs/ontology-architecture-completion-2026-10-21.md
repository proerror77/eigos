# 领域本体补足与架构验证

2026-10-21。实施与复测记录，工程检查状态见末尾。基线为 `07f462e` / `eigos.business@14`，本次为业务模型 15、执行契约 16。无真实下单、付款、预约或常驻部署。

## 结论应怎样理解

原模型已经有通用业务链和六类服务的基础对象，但领域属性和 Data Schema 细化程度不均衡。18 题基线确认了网络来历导航、严格商品属性、跨来源身份依据、酒店套餐、车辆分配/行李/地点，以及候选到执行输入等缺口。另有答题漏读、夹具缺数据和尚未支持的业务动作，不能全部归因于“缺对象”。

这次按 [已批准计划](ontology-validation-and-completion-plan-2026-10-21.md) 补齐上述可验证范围。结构完整、来源可读、动作可执行和实际业务完成分别验收；正确回答“未知”不等于业务流程已贯通，也不据此宣称覆盖所有酒店、汽车或跑腿业务。

## 本次细化的契约

| 业务范围 | 新增或细化 | 判定边界 |
| --- | --- | --- |
| 商品 | 电子、服装、包装商品、通用商品属性 profile；颜色、成色、容量/单位、尺码体系、净含量与套装；订单原条款来源 | 只比较来源明确声明的属性。相同标题不证明同规格；来源缺失、过期或冲突保留未知。 |
| 酒店 | 独立 HotelRatePlan；成人/儿童年龄、房间容量、早餐份数与每日/全住宿期频次、付款时间、取消政策及酒店/房型/套餐/库存关联 | 房型相同不能复用另一套餐或渠道库存。预付、预订确认、住宿完成分别判断。 |
| 即时叫车 | 模式、时区、来源限定地点、行李数量/尺寸、无障碍需求、实际司机/车辆分配和阶段回读 | 接单或派车不证明已上车/送达。实际车辆条件不能仅由“舒适型”等标签推出。 |
| 预约接送 | 接送时段、准确接送地点、载客/行李、分配及接送完成条件 | 预订确认与接送履约是两个终点。改时、取消及加价需要独立动作和许可。 |
| 自驾租车 | 驾驶资格、驾照地域/类别/年限、保险与免赔额、取还地点、验车引用、押金状态 | 取还验收、用车结束与资金结清分开；争议不会由“已归还”覆盖。 |
| 外卖 | 菜品选项组、数量约束、原料与交叉接触、准确配送地点 | 菜品配料不证明厨房避免交叉接触；缺来源不作安全承诺。 |
| 挂号 | 行政就诊类别、初复诊、年龄范围和转诊引用/接受状态 | 只表达行政预约条件，不给诊断或治疗建议。 |
| 行程 | 子行程依赖、来源和时间顺序 | 未新增复杂多供应商自动编排或真实预订。 |
| 跑腿 | 寄件、代买配送、代排队/提交子类型；包裹数/尺寸/包装、易碎/直立/温控/交接、取送窗口；准确交易参与角色 | 现有寄件价格预览不证明额外处理承诺。代买和代排队只有业务定义，未新增执行绑定。 |

领域来源观察沿用严格 schema 和封存回执。新增可选字段不替历史事实补默认值。执行后新分配以独立结果观察关联，不改写执行前批准的候选。

## 共用架构改动

- 网络询价、需求、发布、服务声明、代表关系和展示主体以只读视图进入本体；原 NetworkStore 仍为权威来源。每次导航重新校验当前身份、发布可见性和必要准入；过滤先于分页计数，游标绑定身份与状态。Worker 只消费有期限的准入记录，不读取成员令牌。旧询价缺准入时拒绝共享网络导航。
- 跨来源身份断言绑定两端对象/来源版本、确认主体、依据、有效期及后继撤销。相同、不同、未知、冲突和失效分别表达，不合并 ID 或共用报价、库存、权限。
- 销售/履约/承运等角色绑定准确交易范围和既有主体，ChannelParticipation 继续表示渠道层的角色。收发地址保持私有，不能被当作已认证的个人身份。
- 固定计划的候选上下文与真实操作参数分开。新计划绑定候选身份、对象版本和摘要；历史计划不会被事后加入新参数或重新批准。
- 定义发现默认返回相关动作/函数，`kind=actions/functions` 支持完整分页目录。精确动作 schema 仍可请求；不通过扩大模型读取预算掩盖无关元数据或重复读取。
- `goods.attributes_match`、`errand.quote_matches` 接到本请求范围内的条件判定。常见明确原话可规范化，复杂组合要求准确结构化原文；模型不能从标题、旧条件或其他请求发明事实。

候选选择继续要求明确登记的选择策略。Shopify 展示信息、酒店/车辆沙箱定义不自动成为网络可成交报价；不支持的候选绑定会明确拒绝。

独立代码审查还发现了后置否定、后续指令更正及大量历史询价导致精确读取耗尽预算的问题，已分别加入反例与修复。网络回归包含 45 个正常询价后的精确读取、全部网络类型分页、反向关系和撤回后的游标失效；没有提高读取预算。

## BFO 通用本体复审

依据用户追加要求，已核对 BFO 2020、CCO 2.2、IAO 和 PROV-O 的官方工件，形成 [13 组参考映射](research/bfo-foundation-alignment-2026-10-21.md)，并更新项目术语。当前对象记录、来源观察、计划和实际过程不能只按名称声明等价；商品规格不是具体实物，角色分配记录不是角色本身，程序函数不是 BFO function。领域 Schema 与执行存储继续保留，未引入通用实体表、OWL 依赖或推理机，也未宣称正式 BFO/ISO 符合性。

## 历史兼容

只接受已冻结并核验摘要的 v14 定义，以及此前明确支持的旧版本。迁移检查旧 schema、新 schema 和事实摘要，仅更新定义元数据，保留对象、关系、revision、来源和时间。把新增字段塞进旧摘要，或受本次迁移覆盖的类型遇到未知定义，会整体回滚。其他未获兼容的历史对象不会重新标记为当前对象，读取仍拒绝重解释。执行契约版本不匹配的旧任务保留只读，不自动领取或重放。

## 五条流程的交付边界

| 流程 | 本次应验证的闭环 | 尚未覆盖的外部能力 |
| --- | --- | --- |
| 网络购物 | 来源商品与规格、原报价/结账条款、准确沙箱许可、订单/付款/交付回读及逐项判定 | 真实库存/完整费用/履约、商品专属退货退款绑定与到账 |
| 酒店 | 套餐和房态变化、批准候选、准确许可、预订状态与付款/住宿终点分离 | 真实酒店查询/预订、具体改约取消退款 |
| 即时叫车 | 来源路线/容量、接单及分配、上车/送达/费用阶段、未知结果恢复 | 真实派车、途中取消与实际费用结算 |
| 预约接送 | 明确时段地点/容量、预订/分配/履约分离、未批准变更拒绝 | 真实运营方准入、改时和取消执行 |
| 自驾租车 | 资格/保险、取还验收、争议/押金分离与沙箱回读 | 真实租车方准入、押金冻结/释放和争议处理 |

这些流程分别有反例，而不只依靠只读答题：

- 购物：[交易运行测试](../tests/commerce-agent.test.ts) 检查批准后库存变化、许可撤销、丢失响应与原订单恢复；[商品与分包测试](../tests/product-identity-errand.test.ts) 检查原条款封存、缺少第二包、错误数量和来源冲突。
- 酒店：[候选绑定测试](../tests/fixed-candidate-context.test.ts) 检查已批准对象被同类型候选替换、跨请求与版本变更；[领域字段测试](../tests/domain-schemas.test.ts) 分别检查儿童、早餐数量和频次的满足、缺失及相反证据。
- 即时叫车、预约接送、自驾租车：[领域字段测试](../tests/domain-schemas.test.ts) 分别检查行李/实际车辆、预订与送达终点、驾照/保险/验车/押金；[六类服务运行测试](../tests/service-domains.test.ts) 复用持久领取、准确许可、原操作回读和独立验收，明确自驾资格不套用于预约接送。

最后的无效历史来源导入回归还确认：已完成任务可保留诊断记录，但不从损坏回执补造执行计划、候选或授权；已有有效执行历史保持原样。独立窄范围复查及相关回归已覆盖该修复与静态定义缓存。
