## 准备与操作

在独立的新目录启动一次演练：

```sh
node --import tsx examples/ontology-drill.ts data/ontology-n2-human-session
```

启动后读取该目录的 `access.json`，把本机地址和临时令牌交给参与者使用。它仅访问隔离的合成数据，未连接实际用户、提供者或资金。结束后在启动终端按 Ctrl+C 关闭。

参与者先 GET `/interface`，再按返回的 schema 用 POST `/cases/{题目ID}/tools` 调用通用能力。每次请求带 `Authorization: Bearer 临时令牌`；工具体为 `{"tool":"工具名","input":{...}}`。可以使用普通 HTTP 客户端；若由主持人代发请求，只按参与者的明确指令操作，不推荐对象、关系或答案。

每题最多 20 次工具调用、150 个已读对象和 200,000 字节结果。对象查询另有分页／字节上限；收到 hasMore 时不能把当前页当完整结果。所有业务判断使用接口给出的固定 asOf，而非演练时的现实钟表。题目需要的对象引用也必须先读取，才能作为函数参数；定义中只读到类型并不等于读到了实例。

答题后 POST `/cases/{题目ID}/answer`，填写 `answer`、`evidence` 数组、`assistanceNeeded` 和 `limitations` 数组。该接口仅保存本地答卷，`saved:true` 不代表评分通过。服务记录各题开始／结束时间、查询路径和答卷；额外的口头帮助由主持人补记。
