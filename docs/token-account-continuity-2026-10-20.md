# Token 刷新后的账号与地址确认

不同 Token 不能直接等同于换账号，也不能只凭相同地址判断同账号。当前实现先读取本人地址簿，从经 TLS 验证的官方响应提取明确的 `userId`，然后比较同一任务中前后两次读取的账号身份。确认同号、授权连续且所选地址未变时，保留原确认，不另建 Task、不追加虚构的用户回复。

## 来源与隔离

[官方跑腿工具](https://github.com/meituan/MT-Paotui-For-Client) 的 `confirm_auth` 只报告本地 Token 就绪；Passport 校验当前凭据的响应也不提供账号标识，二者都不能独立证明跨 Token 的账号连续性。

当前官方 `get_address_list` 的 HTTPS 响应在 `data.userAddresses[]` 中提供 `userId`。执行侧的私有响应观察器只监听该条已授权请求，不发起额外网络调用，也不改变官方 CLI 的请求。它同时要求：

- 精确的 HTTPS 域名、路径、POST 方法及当前 `mtcp-ak` 凭据；TLS 对端校验成功。
- HTTP 与两层业务响应均成功；响应大小受限，解压输出也受限。
- 地址非空、全部包含同一个有效账号 ID，且地址 ID 不重复。
- 响应中地址 ID 集合与 CLI 实际返回的地址簿一致。

账号 ID 只经过权限为 0600 的临时文件，在同一次隔离调用结束时删除。持久快照和私有任务上下文只保存由 Vault 密钥计算、绑定 EIGOS owner 的 HMAC，不保存原始供应商账号 ID，不进入模型摘要、用户结果或网络发布。该身份说明两次供应商读取属于同一账号，不是供应商对 EIGOS JWT 会员身份的认证。

Gateway 仍只接收加密凭据，不执行供应商查询。Worker、内部 MCP 和 CLI 继续在调用前后检查连接版本、期限、会员和安装撤权；取消、租约丢失或凭据变化时拒绝迟到结果。

## 连续性与重新确认

新 Token 上传会改变完整 grant revision 和凭据选择上下文。仅同一会员、客户端与安装、且未经过撤销的连接保留 `authorizationEpoch`；该字段受密文认证绑定。它只允许比较身份，本身不证明账号相同。

当前地址簿证明与前一次相同的账号 HMAC、且 epoch 一致时，私有选择记录继续绑定用户当时看到的列表。列表重排或无关地址变动不触发确认。所选地址的 ID 或内容变化会阻止旧选择；名称选择也保留此前绑定的地址快照，不能凭同名地址绕过变化检查。

账号改变、缺少足够身份依据、安装改变或撤销后重连时，原选择不会直接用于新来源。用户须在本任务确认当前地址；物品、重量、服务等仍保留原消息来源。第一次连接的任务可以直接使用其初始明确输入。

空地址簿、缺失／混合账号 ID、响应不匹配或官方 CLI 改用不受支持的传输方式，都不能产生跨 Token 身份证明。已有同凭据续期兼容保留；跨 Token 时保守要求确认。该适配依据当前官方响应，不声称新增了供应商原生账号查询 API。

## 验证

隔离回归覆盖不同 Token 同账号沿用选择、账号改变但地址相同仍拒绝旧选择、身份缺失、授权 epoch 改变、数字选择方向与重排、名称选择对应地址变化、原任务到期后更换 Token、回执保留和取消／撤权边界。

实际官方读取已验证响应观察器能从一次 `get_address_list` 取得账号证明，没有增加来源请求。真实 PA 的跨 Token 原任务验证另行记录；适配器读取和隔离测试不代替该闭环。
