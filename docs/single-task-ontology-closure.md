# 单任务的目标、结果与反馈闭环

本文件记录 v21 的单任务基线。v22 已在此基础上加入[跨服务任务编排](cross-service-composition.md)，下文的“本轮”范围指 v21 实施阶段。

2026-10-25。运行合同 `ontology-execution-v21`，业务本体 `eigos.business@18`。

本轮覆盖一个已注册业务程序内的任务。跨程序目标拆分、跨服务编排、真实付款和新的供应商写权限不在范围内；没有部署常驻实例。

## 目标覆盖

解释器选定能力和输入后，Worker 使用独立模型调用对照原始请求、补充消息、结构化要求、条件及所需交付物。该调用不复用规划会话，不执行供应商操作，不获得业务授权。程序 scope 的纯初始化可以先发生；实际来源读取和业务派发必须等覆盖核查通过。

核查以原文片段记录每项对应的输入、要求与条件。宿主要求每条消息按顺序逐字完整覆盖、所有输入字段与结构化条件都存在映射，拒绝未知引用、遗漏原文、错误任务版本及把未解决内容标记为全部覆盖。冲突或部分满足返回补问／不支持，不能凭某个子操作成功完成整个目标。

`GoalCoverage` 固定请求摘要、能力版本与摘要、规范化输入、实际模型回执和判断。派发与完成重新验证；Agent 输入被替换不能继续。补问改版重新核查，旧覆盖记录保留。固定业务操作之后的回复若改变请求内容，也须核查；原操作的只读终态恢复不依赖重新获准写入。

这是独立语义复核加确定性合同检查，**不是对自然语言理解正确率的数学保证**。两次模型仍可能相关误判；原文分段完整也不证明标签语义必然正确。来源事实、权限和业务完成仍分别由原有确定性验证器负责。核查会增加一次实际模型响应，每份回执标记 `purpose=goal_coverage` 并计入任务模型预算，不计作供应商调用。请求未改变时复用同一覆盖记录。

## Ontology Action 的执行边界

业务程序绑定当前注册的 Ontology Action。统一检查器核对绑定版本、effect／additionalEffects、输入 Schema 与程序实现声明；运行时的动作发现、计划、派发和授权都经过这一边界。投影结果也必须符合 Action 的结果类型。

Action 定义表达业务契约，程序实现负责该领域的来源验证和前置条件，连接器负责单次外部操作。把 Action 加入本体不等于给任何程序或身份授予它；本轮没有放开跨程序调用，也没有移除精确计划许可、来源、取消、租约及未知操作保护。

## 统一结果与反馈

`ServiceRequest.requestedOutcome` 包含实际选定程序，不再在 Agent 完成后仍显示 unresolved。`projectionState=typed_result` 表示已有类型化业务观察，不表示任务成功。当前评估由 `currentAssessment` 指向 `OutcomeAssessment`，历史评估保留在 `assessments` 关系中。

Agent 完成会保存与任务相同的 `delegation.outcome`、逐项要求／条件检查、目标覆盖核查和独立验收依据。待补问／授权是 needs_human；未完成、失败结果不明和取消保持 unknown；明确拒绝为 unsatisfied。任务取消不推导供应商操作取消。结果评估通过 `goalCoverage` 关联当前任务版本的覆盖记录，证据保留原供应商回执引用及真实层级；合成来源不能因此变成真实履约。

任务、结果对象、关系与反馈在同一 SQLite 事务保存。投影失败会回滚任务完成和正面反馈；失效租约或取消后的迟到来源不能把任务改为成功。历史任务不自动转换到新执行合同。

`ExecutionFeedback` 关联原任务及当前评估，同时写入既有 outcome_feedback／capability_verifications 查询。重复保存不增加成功样本。摘要按 owner、程序版本及准确配置摘要隔离；有 tasks:read 的解释器可看到同配置的历史计数，无此权限不注入其他任务的摘要。未知和取消仍在分母中；这些反馈不证明当前可用性，不自动晋级来源或修改程序。

## PA 查询

MCP 和 A2A 继续共用原 Task，不增加提交或授权入口。通过现有 `query_ontology` 读取：

```json
{"object":{"type":"ServiceRequest","id":"实际任务ID"}}
```

读取其 `currentAssessment`，或沿 `goalCoverage`、`assessments`、`executionFeedback` 关系查看过程。统一只读评估接口：

```json
{"function":"taskOutcomeStatus","object":{"type":"ServiceRequest","id":"实际任务ID"}}
```

函数返回当前任务版本的评估、覆盖状态、逐项结果和来源回执引用。它描述验收时的历史结论，不重新访问供应商，不延长报价有效期，也不赋予新授权。已有确定性沙箱售后保持原固定操作合同，不伪造独立语义复核记录；缺少覆盖记录时该新函数不宣称完整目标闭环。

## 验证

`tests/goal-closure.test.ts` 覆盖错城市的独立核查拒绝、原文和条件遗漏、输入篡改、缺少核查器、成功对象链、配置／owner 隔离、补问改版、取消迟到结果、投影事务回滚及 Action 效果漂移。协议回归检查 A2A 结果与 MCP 查询到的统一评估一致。合成模型测试验证接线与失败边界，不作为真实模型准确率统计。

更新代码需停止旧 Worker，使用新合同的任务与兼容本体存储；不能把旧任务库直接视为已迁移。本轮仅同步源码和 CI，部署、历史数据迁移及真实业务仍需按具体授权单独核验。
