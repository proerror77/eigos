# 多 Agent 行程协调：实施与验证

状态：**暂缓执行**。按用户最新要求，先完成[单项服务盘点与逐项补齐](service-inventory-and-implementation-order-2026-10-20.md)。本文件保留为后续组合场景的旧草稿，不作为当前实施指令。

目标：在明确开启的工程沙箱中，由协调 Agent 通过共享本体分派独立的航班、酒店、预约接送和日历任务，直至整段行程可用，或准确停在需要用户调整的部分成功状态。禁止真实下单付款。完成实现、端到端验证、提交推送及对应提交的 CI 回读。

## 复用与调整

- 保留现有任务、Worker 领取／租约、模型读取凭据、固定计划、ActionIntent、准确许可、原键对账、结果投影和验收机制。
- 酒店与预约接送复用 `HotelReservation`、`VehicleBooking` 及领域适配器；补充航班和日历忙闲对象、整段行程、分项委托、受限 Agent 分派、依赖判断和整体就绪验收。
- 协调 Agent 只能执行声明过的本地协调动作和读取动作；每个专业 Agent 有独立任务、模型上下文和执行记录。外部预订仍由已有业务执行器执行。
- 日历日期范围／账号访问许可与预订业务许可分开。各连接器持有自己的沙箱凭据，模型和共享本体不获得原始凭据。专业任务的能力和可读数据由持久分派限制。
- 一版业务方案组合各分项的准确条款。批准范围内才签发已有的分项计划许可，同时检查整体预算与业务依赖；技术任务完成不等于整段行程就绪。
- 来源变更后保留已确认订单和原验收，重新计算受影响依赖，阻止旧方案派发。尚未生效的安排可形成新的方案和授权项；已生效安排需要显式调整，不能随本地任务回滚。

## 交付门槛

- [ ] 版本化本体、模型兼容性及来源证据。
- [ ] 协调 Agent、专业任务分派、持久等待／唤醒及重启恢复。
- [ ] 日期范围内的日历只读许可、分项预订许可、账号与 Agent 隔离。
- [ ] 沙箱完整行程、部分成功停止、变更依赖重算及旧批准失效。
- [ ] 多进程 MCP／A2A 端到端、独立提供方和本体回读。
- [ ] 类型检查、完整测试、构建、差异审查。
- [ ] 当前分支提交推送、相同 SHA 的 CI 成功、远端一致且工作区干净。
