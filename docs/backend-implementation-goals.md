# 后端重构目标与验收

2026-10-17。依据架构审查建议及 [v0.2 设计](architecture-design-v0.2-2026-10-17.md)，按用户最新要求执行：**后端采用新的 Ontology + LLM 架构，不做旧执行架构兼容或旧计划自动迁移。Personal Agent、MCP/A2A 连接及认证保留。** 本文件跟踪实施，不另建平行架构。

## 第一阶段：新后端内核

目标：替换通用委托后端；业务能力、提供者绑定、任务要求、候选、计划、执行和验收各有明确契约。LLM 先理解需求并选择相关本体，再根据实际候选提出计划；程序校验后才执行。

验收：

- 同一个版本化业务能力可登记两个独立提供者；模型不能选择未检索、禁用、无权限或不存在的绑定。
- 需求保存原文、来源、revision、类型化硬条件及偏好。模型不能改写既有要求；计划固定需求摘要和绑定版本。
- 候选逐条件返回 pass / fail / unknown；硬条件失败或未知不得作为可执行方案。
- 计划输入、动作、绑定、依赖、时效及需求版本通过确定性检查。执行和模型调用在数据库事务之外。
- 本地说明和 CSV 用新适配器验证主路径；CSV 全量审计明确拒绝子集，不静默扩大检查范围。
- 旧委托记录保留只读，不自动迁移或恢复执行。前端身份、隔离、幂等、补问和取消保护继续通过测试。
- 通过项目检查，提交、推送并回读对应 SHA 的 CI。

状态：完成。初版内核 f74f106 的118项测试及7次模型调用是 [v2 历史证据](evidence/ontology-backend-2026-10-17/README.md)；本轮已扩展为 v3，并对定义/提供者/配置做摘要固定。v1/v2 计划只读，不作为兼容或执行 fallback。当前代码统一接入文档、美团只读、麦当劳报价和 CSV；最终同步以本轮对应提交的 CI 为准。

## 第二阶段：真实只读供给与事实规划

目标：将获准的真实来源接入 Resolver，迁入已有专用读取能力；为现实需求产生可审计候选与可行方案。

验收：

- 记录渠道、终端商户、商品规格、价格组成、库存/产能、地区、时效、来源及有效期；无法查到的字段保持 unknown。
- 同店跨渠道归组但保留各报价；同名非同款、超时、报价过期、总费用未知和权限不足均不能误选。
- LLM 仅看到有界检索结果及相关本体，不能虚构店铺、动作或修改20杯/预算/截止时间等硬条件。
- 完成一个现实需求的只读比较及方案读回。两提供者是反例测试覆盖要求，现实供给不足时如实报告。
- 真实模型运行、真实渠道读取与合成夹具分别记录；不以下单或支付证明查询。

状态：完成工程与真实只读验收。官方麦当劳 MCP 经新 Resolver 实际查询门店、菜单、详情、计价和复查；真实 Codex + MCP/A2A 完成多家实际门店的20杯美式报价比较。源版本、实际默认规格、门店身份、完整预约窗口、局部覆盖及未知项保留，未伪造库存/产能/取餐时间。POI/地址簿/跑腿报价与文档已迁入新后端，原文和权限仍隔离。见 [E2E 证据](evidence/service-network-e2e-2026-10-17/README.md)。

## 第三阶段：异步动作、恢复与履约核验

目标：由固定计划驱动 ActionIntent、ExecutionAttempt、Observation 和 Reconciliation；业务结果逐条件验收，异常进入查证或补救。

验收：

- 稳定业务防重键先落盘，网络调用在事务外；外部成功后本地崩溃时查原操作，不重下单或换供应方。
- 取消、租约丢失与迟到回执的事实可保存，但不能覆盖当前任务状态；租约失效不得开始新派发。
- 支付、订单、送达、退款各自观察和核验；订单号不等于送达，退款受理不等于到账，部分成功不等于整体完成。
- 独立验收及失败/补救记录有证据；unknown 不进入已完成或成功统计。
- 先用故障注入验证恢复机制。现实操作与现实履约验收等待具体业务授权及渠道条件，当前禁止真实下单和付款。

状态：完成当前授权范围内的工程验收。独立 Gateway、两个竞争 Worker、独立持久 HTTP 提供方验证接单/模拟扣款后崩溃原键恢复、撤销/取消竞态、部分交付拒绝、退款到账读回及原任务不重开。真实 LLM 另行生成并完成三步沙箱计划。ActionIntent/Attempt/Observation、累计预算、逐条件 OutcomeAssessment、关联售后及有界私有反馈均已实现。**现实商家订单/资金/配送仍未运行，现实履约不是本次完成声明**；该门槛按原规则继续等待具体业务授权。

## 最终 E2E 门槛

- 独立 Gateway、两个竞争 Worker 和持久远端测试提供方，经真实 MCP/A2A 完成提交、授权、查询、验收和跨用户隔离。
- 远端接单/模拟扣款后 Worker 崩溃：重启查原业务键，远端订单/扣款各只有一次，原授权和预算占用保留。
- 取消与撤销许可阻止后续新派发；迟到回执仍保存，取消任务不伪装为外部订单已取消。
- 订单号和模拟支付回执不能当作送达；数量不足、超时、未知和验收失败不整体完成。
- 售后建立新的关联任务，退款受理等待到账读回，原失败任务保持原状态，不重复退款。
- 真实 Codex + 麦当劳官方只读接口 + 两种协议完成现实报价比较，并明确真实读取与沙箱写入的证据层级。真实下单/付款禁令保持，沙箱必须限制在本机受控端点。

本轮本地检查：130项常规测试、7项独立进程 E2E、类型检查、构建和差异检查；CI 增加 E2E 门槛。真实模型/来源探针单独执行，不能用这些夹具替代真实商家履约证据。远端对应 SHA/CI 与工作区状态在交付时回读。

## 证据与交付口径

以测试、运行回执及对应提交 CI 更新本文件。开发同步、真实模型决策、真实供给读取、现实交易和履约完成分别核验，不合并成一个完成百分比。旧审查中“兼容旧计划”的建议已被用户本次指示撤销；新架构内部仍固定版本，不能静默更换已选提供者。
