# 滴滴官方 Mock 与 Luna Fast 验收

最终新任务 `49bbdcae-2122-48b3-b699-63540bb22f14` 已完成并通过独立验收。它在隔离的 loopback Gateway／Worker 中运行；MCP 提交、准确计划授权、MCP 回读和 A2A 回读始终使用同一个任务。该验证实例与线上入口分开，不能拿这个任务 ID 去证明公共入口已开放真实叫车。

PA 显式提供起终点要求：北京市“西二旗-地铁站”到“龙泽-地铁站”，车型“快车”。实际 Codex CLI 使用 `gpt-6-luna`、medium reasoning、priority（Fast 请求配置），Agent 自行调用原生 Ontology MCP 选择动作与完成依据。测试观察者只批准展示的一个官方模拟计划，没有模型自动授权或真实下单。

已核验的结果：

- 8 次真实模型调用，8 个原生 Ontology MCP 会话、74 次客户端工具调用；所有会话都绑定原任务，服务端读回执与任务账本的输入／输出摘要逐项一致。
- 官方 Mock 来源调用：地点搜索 2 次、估价 1 次、创建订单 1 次、原订单查询 1 次。创建只有一个意图；查询参数始终为原创建回执的订单号。
- 确认摘要包含路线、车型、原始预估价 15、刷新截止时间和模拟边界。价格不是最终完整车费，零金额授权表示模拟环境不扣款。
- 任务完成用时 235.833 秒，模型调用墙钟时间合计 231.253 秒。完整流程包含一个模型校验纠错，不能据此宣称稳定延迟或相对旧只读估价的提速。
- MCP／A2A 交付物一致，规范 JSON SHA-256 为 `5f061ce35345a492c237b85e296788f963f13723a9ac15ca863d2bdd936d8d9c`。
- 官方 Mock 查询实测返回文字状态。原文与准确 `order_id` 请求绑定；结构化状态码、结构化司机字段和最终车费保持未知，没有将文字编造成行程完成。

详细数据见 [verification.json](verification.json)。原始回复、任务账本和凭据留在私有忽略目录，没有随本记录发布。Mock 的固定地点、订单标识和状态不证明真实账号资格、真实司机、供应商幂等性或履约。

早期联调未通过，暴露了组合输入类型、原生工具参数展示、提交前格式校验，以及模型在创建后错误判断失败的问题。这些运行不计作本次成功证据。最终验证使用明确的 PA 路线要求，也不代表任意自然语言输入都能无纠错执行。
