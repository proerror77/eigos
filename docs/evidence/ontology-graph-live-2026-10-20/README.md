## 验证中发现和处理的问题

1. **交付要求缺少指令来源。** `deliverable` 已在规格属性中，但未进入事实提取及原文引用使用的指令列表。修复后，原始交付要求成为独立指令；仅对尚无执行历史的原始字段遗漏进行受限恢复，没有增加用户确认或改写原 goal 指令。
2. **重复读取耗尽上下文额度。** 在实际任务快照上，完整上下文约 72 KB，第三次同类读取可触发原 200 KB 累计结果额度。修复保留该上限，超限返回小型拒绝回执；未交付对象不能作为证据。早期原生模型的确切第三次调用未保存，因此此处区分可复现路径与已恢复的调用记录。
3. **内部状态进入公共响应。** 旧任务返回包含内部计划、读取定义和历史快照，原生 MCP 传输出现中间截断，无法完整解析。默认业务投影修复后，最终两次原生 `get_task` 均返回可完整核对的业务摘要。历史截断记录保留，没有计入成功的完整回读。
4. **验收捕获上限。** 较早的 PA 捕获进程未完成，但 EIGOS 中的任务及已确认结果继续保存。最终回读使用原有 6 MB 捕获上限，进程和模型轮次均成功结束。最终成功不抹去前面的运行与传输问题。

公开记录不包含原始模型输出；不能从仅有摘要的记录反推每次早期暂停的确切模型选择。无效能力选择的有界反馈、租约／许可失效检查和迟到回执隔离另有确定性回归验证。
