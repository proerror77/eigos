两个 JWT 会员分别提交不同的合成 Token；运行真实 Worker、内部 stdio MCP 和本地 CLI 子进程。两人只看到本人的不同地址和费用，先等待连接再继续同一个 Task，MCP/A2A 读写共享原任务。测试中的 `pt-passport` 是拒绝调用的替身，没有发生操作人凭据回退。CLI 的 HOME／工作目录是独立临时目录。

服务目录测试从获准 listing 到买方私有询价／Task，连接缺失时给出本人授权提示；买方连接后可进入只读候选，发布者仍未连接账号。目录可见性不复制发布者凭据。

失败路径覆盖 scope 缺失、错误 owner／安装、已使用请求恢复与重放拒绝、CAS 冲突、过期、撤销待上传请求、轮换、在途撤销、会员／安装停用、密文篡改、密钥权限／密钥替换／读取目录不一致、浏览器上传拒绝、取消／完成任务不能复活、供应商错误脱敏。SDK 验证固定同源上传、重定向拒绝、回执丢失恢复及不缓存供应商 Token。

数据库／WAL／应用审计中没有合成 Token 明文；任务和模型上下文也没有该凭据。原始测试输出仅用于本地核对，未归档为交付物。

## 结论边界

模型、凭据、地址及供应商返回均为隔离测试替身；HTTP 测试使用 loopback 映射，不能称为真实 TLS／外部 IdP／供应商授权验收。内部回执走真实代码，测试中的 live_readonly 字段不能证明真实商家查询成功。
