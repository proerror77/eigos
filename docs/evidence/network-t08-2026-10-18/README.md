## 关键可观察结果

- 未批准 need 仅在本人草稿中，接收者搜索为空。附加 taskId/精确地址等结构化字段被严格 schema 拒绝；草稿竞争更新拒绝旧 revision。
- 消息必须引用可见主题的当前内容版本；不能把主题外成员加入接收者。父帖、问题和服务引用逐层验证，没有管理员旁路。
- 同一发布请求从 HTTP/MCP 并发提交，仅产生一条回应；另一结果 replayed。相同键改变内容返回冲突。撤回后的 replay/receipt 没有旧正文；父需求撤回后，子消息的回执也返回 unavailable，不能继续报告有效。
- 关闭主题保留获准历史并拒绝新草稿、待发布回应；撤回后主题、消息列表和子消息详情均不再共享。
- 替换需求保留稳定 postId、递增内容版本，旧回应和旧许可不能作用于新需求。替换消息仅更改正文，保留稳定消息身份；竞争替换只成功一次。
- 问题和回答都需独立批准。重复回答拒绝；问题替换后旧答案不可读为新问题的答案。读回稳定消息 revision，可对尚未回答的最新问题版本提交答案。
- 推荐仅接受当前可见服务 publication；引用另一条消息或建立多级推荐被拒绝。服务暂停后引用消息不再呈现为有效线索。没有执行端点解析或调用。
- 默认 3 名响应者、每名 2 次问题；使用上限为 1 的 fixture 验证两份预批准回应竞争同一名额。失败许可未消耗；换 profile、撤回或替换需求不能清空计数。
- 在 published 事件插入点注入数据库失败，publication、message、协作计数、grant 消耗及命令回执全部回滚。移除故障后原键正常成功一次。
- 关闭并重开同一数据库连接/服务后，原键回放到同一消息，计数保持。这是数据库重开测试，不冒称新的独立 PA 运行。
- 旧 T07 need 的幂等升级不改变内容或受众。无关闭权限的安装不能 close；移除成员或撤销安装后，相关读写被拒绝。
- 分页受查看者和可见性版本约束；跨用户游标失败，权限/内容变动后旧游标失效。201 条隐藏前缀可得到空页＋continuation，下一页正常返回可见消息；不暴露隐藏 ID/总数。
- HTTP/MCP 和服务端渲染页面保持同一权限。测试正文中的 script 标签被转义，外部 URL 没有变成执行链接；隐藏 Task ID、精确地址和私人原文没有出现在共享返回中。页面是 HTTP/HTML 集成断言，未将其表述为人工或视觉浏览器验收。
- 原买方 Task 内容与状态完整相等，任务数量未增加；供应方没有获得私有任务。网络默认关闭、真实下单开关仍只能为 false。
