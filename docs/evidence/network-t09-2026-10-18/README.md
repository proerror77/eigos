## 观察与反证

- FollowEdge 唯一、关注/取消幂等、重复同状态不重复产生事件；旧“关注”请求的回放不会覆盖后来取消的状态。同键变内容被拒绝。
- 普通网络写权限或旧安装绑定不自动取得 follow.manage。关注目标须有当前可见主页；不可见目标拒绝，目标撤回后仍可取消旧关系。私有关系无法被其他会员读取。
- 关注过滤后仍只能看到原受众允许的发布；隐藏需求的 ID/正文、私有关注行和目标粉丝信息不进入动态。
- 固定上界用例包含三个原发布及分页期间的新发布：七次拉取（含两次重放和一次无更新查询）覆盖四个唯一 eventId；新发布留到下一轮，重放保留 eventId，读取不改变事件/命令数量。
- need.close 返回独立关闭事件；当前重建只读到 closed，不把旧发布事件作为 open 重放。私有草稿标记没有进入结果。
- 205 条私有事件前缀产生空页＋continuation，随后仍能读到可见发布；未暴露内部序号或总数。limit>20 被拒绝，响应字节预算保持。
- 其他查看者、不同过滤器、伪造的本体式令牌、游标篡改及超过 15 分钟均拒绝，返回 CURSOR_STALE。合法密钥轮换使旧游标失效但不改变事件历史。逐次推进毫秒时钟的回归验证游标签发/截止时间来自同一次取时，不会产生偶发误失效。
- 许可撤销、身份停用和成员移除后旧游标不能读到内容。成员重新接受邀请后也不能恢复旧授权。时间到期即使没有新事件也要求重置。
- 私有关注变化只重置本人的 following 范围；普通圈动态不产生关注通知。
- 在 follow_changed 事件插入点注入错误，关系、事件和命令回执一起回滚；移除故障后用原键只成功一次。
- 关闭并重新打开数据库/NetworkService，原分页游标和完成检查点继续可用，持久密钥、事件数和私有关注保持，续页不重读前页。此处是数据库/服务重开测试，不冒称真实独立 Agent 演练。
- 把事件表恢复为 T08 列结构后升级两次，seq/eventId 不变。被替换的需求和消息保留最新有效版本；已关闭需求只返回关闭状态，旧版本不复活。
- HTTP 与 MCP 并发关注只创建一条关系；二者动态内容相同、回执和检查点可用。撤销后均返回 resetRequired，新的查询为空。
- 会员页要求会话，使用 no-store、正文转义和相同权限；旧游标页面只显示重新同步入口。页面检查为 HTTP/HTML 集成断言，未做人工视觉浏览器验收。
- 原 Task 内容、状态和数量不变；共享结果没有私有 Task ID、地址标记、ownerKey 或令牌。新增模块没有模型/执行器/服务商入口，也没有外发队列。
