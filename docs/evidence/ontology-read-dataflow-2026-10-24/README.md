# 滴滴只读依赖图：真实模型与来源对照

日期：2026-10-24（Asia/Shanghai）。本机隔离 Gateway／Worker，真实 `gpt-6.1-sol` 模型与滴滴 production 只读 MCP；不是合成测试或真实叫车。完整配置、自然语言目标、任务身份、来源原文、账本与回执留在本机私密验证目录，本文只归档脱敏计数与耗时。

## 同配置对照

两个实例只在代码版本、loopback 端口、本地数据库／日志路径和开发访问令牌上不同，使用同一个来源账号绑定、模型程序与配置。依次运行旧 1 → 新 1 → 旧 2 → 新 2，四次目标文件逐字节相同；本地重负载测试已结束。每个变体只有两个样本。

| 指标 | v19 | v20 |

| 受理到独立验收，样本 1 | 31.069 秒 | 20.261 秒 |
| 受理到独立验收，样本 2 | 32.293 秒 | 27.746 秒 |
| 平均任务耗时 | 31.681 秒 | 24.004 秒 |

| 每任务真实模型响应 | 3 | 1 |

| 每任务宿主本体读取接口回执 | 21 | 21 |
| 其中 evaluate_ontology 回执 | 5 | 7 |

该小样本中平均任务耗时减少约 **24.2%**，模型响应减少 **66.7%**。本体接口回执没有减少，新增的来源选择由程序计算；节省来自较少的串行模型往返。模型运行阶段仍占主要时间；响应次数减少不等于耗时同比例减少。模型阶段包含进程／客户端与请求等待，不能解释为供应商纯推理时间。供应商读取包含两个地点搜索和一次估价；并行跨度的合计也不能直接当成端到端耗时。

v19 使用两个模型选定图和显式模型完成；v20 使用一个模型选定图、一份实际输入绑定证据，以及模型事先选定的条件验收。两者都保留实际来源和独立验收，没有减少供应商读取或伪造模型已看到的结果。

## 动态组合与证据

另一个真实目标只要求搜索公共地点。相同 v20 运行时代码由模型选择了一次搜索和条件验收，**没有追加估价**：1 次模型响应、1 次供应商读取，任务 13.472 秒。它与仅估价目标使用不同的模型选图，未修改执行器。

每个对照样本及该变体均通过另一 MCP 客户端读取，并与调用方 A2A 交付物、持久任务／意图／尝试及原始来源文件摘要核对：

- 所有业务 effect 都是 read，全部来源为 live_readonly；无订单、付款或预算预留。
- 来源工具与版本化 Ontology 绑定一致，原始响应 SHA256 全部匹配。
- v20 原始模型回复在真实来源之前；实际参数来自其选定的上游已接受对象和声明纯函数，尝试输入摘要相符。
- 参数求值与完成检查使用新的 Worker 读取回执，明确为 `origin=worker_context`；没有把这些后来的读取记成模型上下文。
- 完成记录保持原 execute 决策与模型回执，注明 `mode=planned`；当前来源、路线、任务版本和硬要求均独立检查。

实现说明见[只读数据流合同](../../ontology-read-dataflow-2026-10-24.md)。去除目标、地址、来源原文和任务原始标识后的机器记录见 [summary.json](summary.json)，包含模型用量、每次来源读取耗时与宿主读取接口的回执计数；这些接口回执不等于全部内部纯函数调用。

## 验证范围与限制

本地全量 619 项通过；随后源选择的保守地址约束由 60 项当前专项回归覆盖。类型检查、构建、8 项进程 E2E、安全清单与 diff 检查通过。安全清单更新没有安装新的运行时权限，也没有授予权限。最终远端提交及 CI 状态单独核验。

两次原常驻宽目录样本和一次较早的候选试跑也保留在机器记录的 exploratorySamples，因目录、运行负载、轮询连续性或候选版本不同，没有纳入上述平均数。不得直接用其 80 多秒与当前隔离样本比较并宣称改造提速比例。

这是同一清楚路线上的有界结果，不证明所有任务都只需一次模型响应，也不构成 P95 或普遍性能保证。歧义、空来源、错误城市、跨角色地址、取消、租约／请求版本与结果条件失败另有回归覆盖；需要新判断时仍回到模型或用户。

不含原生 Grok 对话界面的派发与回报耗时。外部独立观察器在任务完成后核验，不计入任务受理至验收时间；来源新鲜度按验收时点回放。估价不证明完整最终车费、可叫到车、接驾或行程完成。常驻实例保持原版本，本轮只验证隔离实例。
