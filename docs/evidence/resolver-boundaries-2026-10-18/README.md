# Resolver 发现期限与取消边界

2026-10-18。基线为 `96d623c09a598d6991670071bb86ca615907bfd6`，在独立副本验证；没有修改共享工作区、常驻服务、凭据或真实供应商配置。

## 缺口与修复

原 Resolver 直接等待 `source.discover()`，仅传入 `AbortSignal.timeout(60000)`。来源忽略信号时，60 秒期限和调用方取消均不能结束等待；来源迟到返回后也可能登记候选。静态绑定的 `prepare()` 同样依赖适配器配合取消。

Resolver 现在独立竞争操作结果与取消信号：

- 每个发现来源保留 60 秒期限；超时记为 `timeout`，继续查询后续获准来源。
- 调用方取消直接向上拒绝，保留原取消原因，不调用后续适配器或来源。
- 迟到成功不登记候选、不改已返回结果；迟到拒绝有处理器接收。
- 完成、失败或取消后清理自有计时器与监听器。
- `prepare()` 保留原有时间策略，仅补充取消等待和返回时的取消检查；Worker 原有整体期限、租约及取消保护继续生效。

这保证异步等待能够结束，不能强制终止忽略信号的上游操作，也不能抢占阻塞 JavaScript 事件循环的同步代码。业务动作派发与履约核验不在本次修改范围。
