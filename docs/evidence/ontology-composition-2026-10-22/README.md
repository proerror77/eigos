# 本体组合修正：基线、实现与验收证据

记录日期：2026-10-22。已批准计划见[实施计划](../../ontology-composition-foundation-plan-2026-10-22.md)。

本目录的 P0 记录是隔离内存库中的定义及源代码注册清单。它没有加载会员配置、访问供应商、创建任务或签发权限，不能作为公网配置、来源可用性或跨服务完成的证据。

## 基线

[机器可读清单](p0-baseline.json)固定了：

- 执行代码基线 99ca9104c71364ce5c586299a43d18bd9410d7b3，以及 215 个应用/内核/依赖配置文件的实际摘要。
- 注册库解析后的 eigos.business@16，而非只读取模块中的原始 v15 种子。
- 153 个对象类型、7 个接口、655 条关系、55 个动作和 40 个函数。
- 7 组程序声明（包含通用受管数据引擎）及 15 项适配器能力声明。
- 审计脚本本身的内容摘要；可以用 node --import tsx examples/audit-ontology-composition.ts --output <新快照路径> 重建当前清单。不可覆盖此基线来掩盖后续变化。

## 已确认的缺口

| 编号 | 当前可观察事实 | 修正方向 |
| --- | --- | --- |
| G01 | 14 个动作同时出现在多个程序声明中，例如相同购物动作服务不同运行配置，ReadSavedAddresses 同时服务报价和地址读取 | 动作名不能唯一确定执行来源；每步必须选择并固定准确绑定、上下文和配置摘要 |
| G02 | 6 项适配器操作缺少共享本体中的准确 Action 定义：prepare_brief、compose_document、audit_csv 及三个旧读取操作 | 为仍需参与组合的工具补准确的动作/结果契约；旧声明明确退役或限定兼容范围，不能无版本别名替换 |
| G03 | 9 个本体动作没有可执行输出契约和运行注册 | 主要属于请求、选择、授权、验收等概念或规划记录；逐项保留不可派发语义，不将其自动变成模型可执行权限 |
| G04 | grounding 要求选一个 capabilityRef；Agent 状态和计划固定一个 programRef/programDigest | 固定用户目标与条件，执行范围改为逐动作绑定；保留原模型读取和决策凭据 |
| G05 | 固定 planner 校验步骤数、动作、依赖和输入必须等于 recipe | 跨动作业务拓扑由模型提出；必要的供应商原子协议继续由实现保证 |
| G06 | schema、输入校验、授权、执行、恢复、投影和完成判定均通过当前 program 调用 | 迁移这些共用依赖，不能只移除 actionIds 检查 |
| G07 | initialize / prepareRequest 产生各领域请求上下文，现有领域校验依赖这些准确根对象 | 将纯上下文解析与执行动作区分；建立每个绑定的独立上下文，不混用另一个程序的范围 |
| G08 | 任务金额占用按 job 累计，但上限来自当前单个 grant.maxAmount | 分清任务总预算、单步准确许可和同一业务承诺的占用语义；先添加组合反例，再改变约束 |
| G09 | program.complete 证明该程序范围的结果；任务层没有统一跨程序必需条件覆盖 | 各领域验证器提供有限事实，任务级评价逐项汇总所有必须条件 |
| G10 | 共用编排器包含包裹报价解释、付款等待等具体业务判断 | 将具体业务语义移到对应契约/领域处理器，保留通用授权、等待与恢复机制 |
| G11 | UCP 确认阶段要求引用一个已完成的准备任务及其固定计划 | 增加准确的已接受准备结果引用，使一个目标内的组件结果可用；不能提前把整个任务标为完成 |
| G12 | 若干 adapter.prepare 同时做输入校验和实际来源读取 | 明确区分纯校验/上下文解析与模型可选择、可审计的来源读取；不能把触网动作藏入初始化 |

G03 的九项为 RequestDeliveryQuote、SelectOffer、SubmitServiceRequest、ProposeServiceExecution、AuthorizeProposal、ConfirmSimulationQuote、RevokeProposalAuthorization、AssessServiceOutcome、RequestServiceRemedy。它们目前无执行绑定。尤其授权相关概念不能因此成为模型给自己签发许可的可执行动作。

G02 的 delivery.quote@1 和 address.book.read@1 属于旧读取声明；当前能力工厂只从该旧读取数组选择索引 0 的 geo.search，并另行注册较新的 Agent 程序。迁移清单需要保留这一区别，不能将所有声明误报成当前已启用能力。

## 第一条受控迁移切片

先采用已有的商品目录读取与文档生成两个独立绑定：目标要求取得当前来源商品信息，并交付基于这些已接受信息的比较文档。这样既包含现有 AgentProgram，又覆盖缺少共享 Action 定义的旧适配器路径，可以直接检验结果引用及整体目标验收。

- 来源使用明确标记的隔离提供方；文档由真实模型执行。第一条结果只证明受控组合，不证明真实库存或履约。
- 驱动只给业务目标、所需材料和范围明确的测试授权，不给模型动作顺序。
- 目录结果必须独立验证后进入本体，后续文档输入绑定该结果，不能仅复制任意模型文本。
- 正常、来源事实改变、第二服务失败三组变体分别保留读取、选择、调用、结果和完成检查。
- 随后加入现有配送报价绑定，验证第二个外部来源、地址角色、重量和费用条件。真实只读来源仍需实际准入验证；未取得来源时保持该关卡未通过。

## P1／P2 基础实现

- 已增加具名对象／值端口、角色、结果阶段、单位、币种、位置角色、时区、来源与新鲜度契约。端口是发布定义的一部分，改变即改变模型摘要；接口动作映射也检查端口及证据强度。
- 前置／后置条件使用已有可信、精确版本的校验器。外部写操作必须声明只读原操作恢复契约；补偿动作单独声明，不产生执行权限。
- 跨动作结果携带原 Intent／观察、身份、任务、请求版本、本体发布、来源、有效期和对象快照。仅持久接受的原观察可供后续动作读取，过期、篡改、换角色或已变化对象被拒绝。
- 同一动作的独立程序绑定分别返回。Worker 与 PA 共用任务范围发现，支持分页和类型／效果过滤；来源撤权、配置变化或游标跨任务使用不能继承原可用性。
- 最近的组合契约、绑定发现、动态编译器测试通过；本体规划回归 14 项通过。类型检查及差异空白检查通过。后续代码变化后仍需运行最终完整检查。
- 已保存准确 v16 定义快照，模型摘要仍为 `9cc72c92efa54600967979971dc0e568d01d849b683bbe4e7d6d8931150eef57`。新的运行契约尚未提升默认发布版本。
