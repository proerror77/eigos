# S5 验证记录（2026-10-25）

本轮实现与隔离验证覆盖离线复制迁移、Node／Python PA v2、原生来源安全投影、浏览器派发复核和受限原操作查证。详细合同与 T01–T18 对照见 [S5 说明](../../security-s5.md)。

真实常驻数据库通过 SQLite 备份形成闭合快照，原服务继续运行。迁移保存 48 个任务、568 个对象、1053 条关系、各 114 条执行意图／尝试／观察和 55 条幂等回执；会员快照逐字节保留。5 个明确的私有目录共 130 个文件被复制并完整校验。26 个对象满足候选绑定证明，542 个历史对象仅保留为私有归档；激活绑定和自动安全许可均为 0。源副本未被改写。

可公开摘要位于 [summary.json](summary.json)。原始数据库、访问凭据、环境文件、来源响应、浏览器证据和完整测试输出仅保存在私有目录，未提交到仓库。

用户随后完成两个设备登录。使用现有 Auth0 配置与现有私有 HTTPS 接入，两个安装经独立签名验证对应同一活跃会员，凭据文件彼此独立；提供者客户端、令牌期限与账户策略未改变。独立 Python PA 验证了任务隔离、同 requestId 重放与自己的 v2 查询；独立 Worker 进程验证了撤销 B 后续租失败，A 仍可续租，B 的 PA 请求被拒绝。B 的试验 grant 保持撤销，最终常驻须建立新的明确许可。

定向测试曾发现并修正 SDK 上下文请求方式、沙箱来源的旧开发身份限制、原生海关参考字段比较和重复权限复核耗时。合成测试身份采用足够完成多步骤流程的 15 分钟令牌寿命；没有放宽 Worker 的租约。完整验证以最终结果为准，原始失败输出保留在私有测试目录供排查。

早期阶段本地验证：`npm run check`、完整 687 项 `npm test`、`npm run build`、11 项编译后 E2E、83 路径的 S0 清单及 `git diff --check` 通过。真实联调修正了 foundation 个人来源启动检查、摘要规划视图过度展开和预备读取超出上下文预算的回退；相关回归纳入完整测试。运行代码提交 `a0137be` 的 [CI](https://github.com/proerror77/eigos/actions/runs/40158415123) 已成功，工作流的准确 SHA 与全部步骤通过独立 GitHub 工具回读。

迁移最终检查另覆盖了“没有活跃 grant，但已有新的策略变更”的情况：启用前 verify 拒绝此状态。4 项迁移与 8 项清单回归通过，常驻快照的原始迁移副本再次通过 verify；新库一旦承接授权／撤销事实就不能用于自动恢复 legacy。

迁移拒绝尚未完成的撤销协调 fence，要求先在原权威状态中解决；不会把“会员库还显示有效、业务拒绝已写入”的未决状态变成可重新授权的新实例。此拒绝路径纳入迁移回归。

真实来源摘要见 [live-readonly.json](live-readonly.json)：Shopify 公开目录、美团原白名单内地点查询和本人地址读取均由模型选择动作后完成，独立 PA 接受结果；电话未交付，完整地址簿未进入模型读取。Luma 既有报名当前为 canceled，浏览器、来源桥和独立 Ontology 读取一致；这不证明报名成功，也没有重新报名。本次 Luma 费用数据不完整，明确保留未知。

早期滴滴真实地点读取返回上游账户额度耗尽（JSON-RPC -32001），当时没有通过正向真实查询验收。用户已选择保留原常驻，等待滴滴额度恢复并通过真实只读验收后整体切换；此前不含滴滴的候选配置未被选择。在该检查点，常驻仍为 legacy，最终切换尚未执行；后续完成记录见下文。所有本轮外部业务调用仅为读取，没有下单或付款。
