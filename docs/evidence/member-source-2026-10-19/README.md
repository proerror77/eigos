## 实现证据

- 一个受信连接只允许一个准确的 issuer／tenant／subject owner；Gateway 还核对 memberId、已开通状态、issuer 与邀请网络准入。
- 共享业务库只保存连接与身份的准入摘要。连接文件、读取程序目录及会员撤权状态在 Worker 和内部 MCP 路径重查；Gateway 不执行来源程序。
- 凭据继续由既有 pt-passport／官方 CLI 读取。新增记录和工具没有复制令牌，也没有来源认领或共享凭据 API。
- 既有 delivery.quote@2、地址补问、源回执、本体对象、私有询价、TaskService 和权限规则直接复用。

新增 7 个源码测试及 1 个独立 CLI 进程测试。关键反例：

1. 其他会员、旧本机开发身份、不同 owner 不能获取绑定或调用读取器；看到服务不产生调用资格。
2. 其他会员建立自己的需求后仍不能用这份绑定转换为私有询价，且凭据工具调用数为零。
3. 获准会员的私有询价交给现有 Worker，经实际 stdio MCP 和本地命令接口处理地址补问；通过 A2A 回复、MCP 读回，原任务只有一个。
4. 连接撤销、过期、身份变更、缺失、格式无效、权限过宽、符号链接、未准入或读取程序目录不一致都拒绝。
5. CLI 返回期间撤销连接，结果不保存为地址准备上下文，后续预览没有发起。
6. 会员停用后的持久撤权记录被独立 Worker 数据库连接读取；单纯重新批准会员不恢复来源资格。
7. 精确身份不匹配的连接无法通过 Gateway 启动校验；公开主机、生产、无连接 JWT 和真实订单开关仍被拒绝。
8. 操作者 CLI 仅可绑定明确准入会员，不覆盖已有文件；inspect 不输出身份原文或凭据；revoke 使已创建的读取器立即失去资格。

## 测试与现实的区别

新增集成测试使用合成 JWT 身份、模型决策、地址和本地 CLI 替身；实际运行的是 Gateway、Worker、SQLite、stdio MCP 和子进程边界。协议中的 live_readonly 回执由内部读取服务器按其接口产生，但测试供应商是明确替身，**不能据此宣称本轮真实美团查询或真实 PA 验收通过**。

本轮没有读取真实令牌或保存地址，没有启用真实连接，没有更新本人常驻服务，没有部署、交易、订单、付款、预订或对外发送。人工演练继续单列；T13 的实际 PA／来源与成本时间对照尚需在另行启用本人连接后运行。
