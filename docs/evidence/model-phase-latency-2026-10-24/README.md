# 模型耗时分段与输出简述对照

2026-10-24，隔离本机 Gateway／Worker、Codex CLI 0.159.2、实际 `gpt-6.1-sol` 与滴滴 production 只读 MCP。模型、推理／服务档位设置、权限、自然语言任务和供应商读取保持相同；原常驻实例未切换。

## 能测到的边界

上次 22.5 秒的历史回执只记录请求／确认／完成，不能事后回填流式时间。其已有记录约为：会话准备 2.2 秒、请求确认几毫秒、确认后至完成约 20.3 秒。本轮补充客户端单调时钟，记录 `turn/start`、首个最终输出 delta、最后 delta、最终 item 和 turn 完成事件；事件早于确认到达时保留原到达时间。

这些是[官方 app-server 协议](https://learn.chatgpt.com/docs/app-server)中的事件。协议版本以本机 CLI 生成的类型核对。只保存事件时间、字节／次数和摘要，不保存隐藏推理或摘要文字。

| 客户端阶段 | 优化前平均 | 优化后平均 |
| --- | ---: | ---: |
| 进程、线程及请求准备 | 1.992 秒 | 1.820 秒 |
| 请求发出 → 首个最终输出 | 6.302 秒 | 5.615 秒 |
| 首个 → 最后可见输出 delta | 13.619 秒 | 9.182 秒 |
| 最后 delta → JSON 解析完成 | 0.359 秒 | 0.066 秒 |
| **模型阶段合计** | **22.273 秒** | **16.682 秒** |
| 请求本地确认（已含在首输出等待中） | 11.4 毫秒 | 6.8 毫秒 |

本轮优化前的约 22.3 秒与历史约 22.5 秒是不同样本。准备约 2 秒，主体是首输出等待与可见输出。本地 RPC 很快得到确认，并不证明上游模型没有排队。

首输出前仍混合网络、上游排队、输入处理及未暴露的模型工作，当前接口无法进一步分离。可见输出窗口也含流传输和缓冲，不能当作纯服务端生成时间。推理事件仅说明收到一个事件，不代表实际推理开始。没有 delta 时记录 `completed_item_only` 与 `visibleOutputMs=null`，不能记成零生成时间。

## 采用与放弃的优化

**采用：** 保留原有结构化输出与宿主合同，只要求成功计划的说明／理由简洁、为新步骤与要求选择短且唯一的本地 ID；已有 ID、完整业务输入、硬约束、原文引文、来源消息、动作和依赖不能省略。补问仍需明确实际缺失信息。没有改变模型或推理强度，没有降低来源检查或把流程写死。

**未采用：** 曾试跑把 `finalJson` 字符串改成直接 JSON 对象。两次输出 token 明显减少，但模型阶段分别为 19.690／20.509 秒，相应诊断对照为 16.694／21.245 秒，没有得到耗时改善证据，因此该格式和会话池改造已撤回；最终代码不包含它们。原始实验与补测记录单独保留，不混入主对照。

## 本轮交替实测

| 样本 | 优化前任务 | 优化后任务 | 优化前模型 | 优化后模型 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 22.027 秒 | 21.160 秒 | 20.440 秒 | 19.713 秒 |
| 2 | 25.573 秒 | 15.040 秒 | 24.107 秒 | 13.653 秒 |
| 平均 | **23.800 秒** | **18.100 秒** | **22.273 秒** | **16.682 秒** |

每版两个样本，按前 1 → 后 1 → 前 2 → 后 2 执行；同一目标文件逐字节相同，主对照在全量本地测试之前完成。每任务均为 **1 次模型响应、1 个线程、3 次供应商业务读取**。回执 `output_tokens` 平均 1011 → 950.5，约减少 6%；观测到可见输出窗口约减少 33%、模型阶段约减少 25%、任务约减少 24%。

**不能把全部耗时差异归因于提示优化。** 输出 token 的减少远小于耗时变化，首输出等待与解码／流速度有明显波动；这是同一路线小样本的观测结果，不是稳定提速、纯生成速率或 P95 保证。主对照输入未命中缓存，模型／权限／供应商调用未改变。

另一个真实目标只要求搜索公共地点。优化后模型自行选择一次搜索与条件验收，没有追加估价，独立回读通过。该变体与本地测试重叠，只用于验证动态选图，不纳入上述性能均值。

## 验证与证据

- 四个主样本的调用方 A2A、独立 MCP 和持久任务／意图／尝试一致；原始供应商响应摘要全部匹配，业务 effect 全部 read，没有订单、付款或预算预留。
- 模型选定图与参数来源仍逐项核对；四个样本解释出的任务输入和唯一硬约束含义相同，允许模型选择不同本地 ID。完整原文引用继续通过原有来源检查。
- 新观察器检查分段之和、准备子段之和、流式／无流式的区分；测试覆盖早于确认的事件、非本 turn 数据、错误线程、隐藏文字不保留、会话复用、取消及原有禁止工具策略。
- 本地全量 626 项通过；新增事件相关反例由当前 34 项专项复跑通过。类型检查、构建、8 项进程 E2E、安全清单及 diff 检查分别验证。精确提交的远端 CI 状态单独回读。

脱敏机器记录见 [summary.json](summary.json)。完整目标、任务 ID、来源与事件时间留在本机私密验证目录；归档不含地址、令牌、原始任务标识或隐藏推理。这里计时不包含原生 Grok 对话界面的派发与回报，也不证明估价以外的业务履约。
