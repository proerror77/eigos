## 实际经过

1. 真实 PA 只提交一次任务。本人来源连接后，Worker 从旧 Token 的实际地址簿响应取得账号依据，并展示本人地址选项。
2. 将当前列表中的地址 ID 与内容同此前本人已确认的路线核对。PA 在原 Task 补充一次已确认信息；没有要求用户重新确认业务事实。
3. 通过既有私有连接接口把 EIGOS 使用期限缩短至12秒，观察真实时钟到期，原 Task 进入 `auth-required`。该步骤没有伪造任务状态，也不声称供应商 Token 本身已过期。
4. 本人在美团 App 完成官方授权，新 Token 与旧 Token 的实际值不同。PA 通过私有接口上传新凭据并恢复原 Task，完整连接版本变化、授权 epoch 保持。
5. Worker 重新读取地址簿，确认供应商账号标识一致，再沿用原选择读取两条地址详情、进行一次费用预览并完成任务。没有额外地址／物品确认，没有替代 Task 或取消操作。

本人 App 授权属于取得新凭据的必要平台交互。此记录证明不同凭据的同账号连续性及业务确认保留，不声称已经验证无需用户交互的供应商静默刷新接口。

- 19 次实际 Worker 模型调用保留，恢复前8次未清零；恢复后复用已有需求解释。
- 全任务共5次官方只读调用：两次地址簿、两次地址详情、一次预览。账号依据来自同一次地址簿响应，没有增加来源调用。
