# 实际 PA 与 Agent 的交易、跨境及履约沙箱验收

2026-10-20，现有 Grok Bot／Monk PA 在用户连接的 Mac 上，通过原 A2A 客户端提交一项业务目标。EIGOS 使用真实模型查询 Ontology、选择业务动作、处理必要补问、申请准确计划授权并验收；Monk 随后读取原任务终态。独立观察器核对模型、来源、授权、本体与 PA 交付内容后通过。

**实际 PA → A2A → EIGOS Ontology＋LLM → 独立签名沙箱来源 → 原订单／付款／逐包裹交付读回 → Agent 验收 → 同一 PA。**

PA 和模型执行是真实运行；商家、保存地址、商品、库存、清关规则、费用、订单、付款和物流全部为合成数据。服务只运行于本机 loopback，没有真实商家购物车、订单、付款或实际运输，也没有进行公网部署。

## 回传范围与发现的差异

原始订单来源的 `fulfillment` 仍为 `pending`；独立 Delivery 记录为 `delivered`。模拟器在创建订单时保存前者，独立物流查询不会回写订单字段。因而不能把此差异解释为已经证实的“订单读取早于送达”。本次交付验收依据独立交付事件和本体中的零剩余数量，保留订单原字段；这不证明跨来源状态自动同步。

Agent 已从商品和清关来源查询并核验巴西原产地，验证记录保留了这些证据；当前最终 PA 交付物未展开原产地和商家注册地字段。不能将“Agent 已查到”描述成“PA 的最终业务结果已包含全部跨境字段”。

PA 首次口头摘要把检查条数误报为 5，并猜测状态差异的时间原因；原始回执实际为 14 项通过。同一 PA 重新读取后更正了条数、删除未核实解释，并将报告中误标单位的付款金额改为“27000 最小单位，即人民币 270.00 元”。原始回执及交付文件摘要未变，没有重做业务。界面核对记录见 [`pa-ui-observation.json`](pa-ui-observation.json)。

```sh

```

原始私有目录包含来源签名验证所需的本机配置引用与逐次回执，未将凭据归档到仓库。该测试证明沙箱中的主动事实查询、必要补问、准确授权和独立验收；真实商家授权、库存、海关规则、支付清算和运输仍需真实来源接入及另外的业务授权。
