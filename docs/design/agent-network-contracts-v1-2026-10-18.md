## 已确定的选择

1. 不重建本体目录、对象库、九个函数或现有三个查询入口。
2. 网络表与任务/本体共用业务 SQLite 和事务连接；使用独立 NetworkStore/NetworkPolicy，不能用公共 owner 绕过私有对象隔离。会员凭据库继续独立。
3. owner 仍来自 issuer+tenant+subject；actor 从验证成功的安装登记派生。profileId 是稳定公开引用，不是凭据或任务 owner。
4. 新网络功能默认关闭；未来新增 network:read/network:write scopes 和主体网络资格，旧令牌不自动获得网络能力。批准发布只走现有会员会话的控制面，不提供 bearer 批准接口。
5. 首期采用“精确内容、单次发布”的 PublicationGrant；批量确认多个草稿可以减少操作，不能形成无限自动发帖许可。关注本身私有，不公开粉丝图。
6. 服务圈分享使用批准时固定的接收主体集合，并与当前成员/停用状态取交集；新成员不自动看到历史内容。
7. 网络写入、事件、许可消耗及幂等回执同事务；推荐转询价和 Task/对象关联也同事务。网络调用、模型调用不在事务里。
8. 引荐是非权威资料；选定 Listing 的受控 source/binding 限制由服务器建立，不能来自帖子 URL。只有买方的私有指令进入需求原文。
9. 当前 N1 的配送结果是估价、费用覆盖未知、五分钟本地刷新限制。可以完成查价，不得据此声称预算合格或可承诺履约。
10. N2 独立演练、N3 新对象的真实 PA/来源验证、以及任何现实交易都仍需分别完成；本组设计不替代它们。

## 模块与事实责任

| 已有/拟新增模块 | 权威职责 |
| --- | --- |
| MemberStore / AgentRegistrations（已有） | 会员、安装、OAuth client、会话及凭据状态 |
| TaskService / JobStore（已有） | 私有请求、固定要求、任务、动作、幂等与执行状态 |
| OntologyModel / ObjectStore / functions（N1 已有） | 版本化定义、owner 私有对象、关系与有界计算 |
| projectTask（N1 已有） | 当前任务及受控回执到业务对象的唯一投影入口 |
| NetworkService / NetworkStore（新增） | 圈、资料、发布内容、消息、关注、事件和共享视图 |
| NetworkPolicy / PublicationApproval（新增） | actor/受众权限、许可批准/消耗/撤回；不签付款许可 |
| InquiryBridge（新增内部服务） | 网络线索与私有 Task 的原子关联；复用提交逻辑 |
| 私有选择快照（新增支持记录） | 记录买方选择时的准确报价版本；不是新的价格事实源 |

不增加通用 ORM、第二套任务执行器、图数据库、消息中间件或公共联邦服务。新增网络领域定义可复用 N1 定义编译器，但不能向 eigos.business@1 静默添加跨用户关系；网络记录不进入现有 query_ontology。

## 跨契约演练结果（设计检查）

- 同 owner 不同安装冒用 profile：D01 拒绝；不改变原任务 owner 规则。
- 发布提交成功但响应丢失：D02 按原 requestId 返回引用；当前已撤回则不重放旧正文。
- 发布与许可撤销并发：共享事务先后决定，撤销先提交则发布失败；发布先提交则随后撤销隐藏内容。
- 推荐转询价时进程崩溃：同库任务、关联、幂等回执全有或全无，不重建第二个任务。
- 接到未来五分钟内的配送估价：D03 可报告查询结果；费用未知使“总价不超预算”仍 unknown。
- 卖方回复“同意付款”：D04 仅保存消息，不生成买方许可。
- 帖子撤回：停止共享；已创建私有 Task 不因此取消，仍按原授权处理。

以上是文档结构与状态推演，不是测试执行结果。验收用例和设计覆盖见各分册末尾。
