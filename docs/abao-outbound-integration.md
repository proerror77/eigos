# EIGOS → 阿宝接入记录

核验日期：2026-10-15。状态：尚未接通；待取得面向外部智能体的正式接入权限与接口契约。

## 目标与方向

用户向 EIGOS 提交任务，由 EIGOS 调用阿宝／支付宝智能服务，接收补问、用户确认要求和执行结果。EIGOS 是调用方；不是把自有服务上架供阿宝调用。

## 已核实的依据

- 支付宝在 W3C 的公开材料介绍 AHA-SDK、Agent 注册／发现／认证／证书签发，以及服务查询、意图澄清、执行衔接。材料涉及服务端和客户端协作，不能据此假定支持纯服务端调用，亦未提供足以实现客户端的地址、报文、签名与版本契约。
  https://www.w3.org/2026/04/hangzhou-webevolve-liu-yunxuan.pdf
- AI 开放平台公开展示资源订阅和外部应用调用能力，但这不等于开放阿宝完整任务执行接口。
  https://open.alipay.com/ai/ai-resource-center/welcome
- 本次浏览器读回申请页显示已有申请提交成功、审核结果以短信通知。当前申请选择的是输出自有能力，和本次调用阿宝的目标不同。未由本次操作提交或修改申请；申请成功不代表权限获批。
- 移动端智能体支付文档只定义预下单、支付加签、客户端唤起和通知；要求签约且当前不支持沙箱。它不是阿宝任务调用接口。
  https://aipay.alipay.com/docs/agent-pay/mobile-agent-pay.html

## 代码差距

已阅读 src/tasks.ts、src/a2a.ts、src/domain.ts：现有 A2A 是入站服务端；TaskService 同步完成 brief.prepare；任务状态仅有 input-required、completed、canceled。尚无阿宝出站客户端或实际业务执行器。

正式规范确认后需要实现：

1. 独立出站适配器：固定且经过核实的官方端点、协议版本、身份与签名机制；不将 EIGOS 入站访问令牌转交给下游。
2. 执行任务持久化：内部任务与远端任务关联，明确运行中、等待用户、失败、取消和结果未知状态；两种入站协议共享同一业务状态。
3. 用户授权与客户端交接：按平台规定承接登录、卡片或确认流程，不能把 tasks:write 当成支付授权。
4. 重试与恢复：按官方幂等契约处理；超时不代表失败，取消请求不代表远端已取消。业务完成须以可核实的履约结果为准。
5. 验证：类型检查、现有 MCP/A2A 测试和构建；新增针对出站认证、重试、补问、状态恢复与用户隔离的测试。真实联调与本地模拟分别记录。

## 向平台确认的必要信息

- 是否允许 EIGOS 这类第三方云端智能体作为阿宝调用方；是否要求手机／终端 SDK。
- 正式接入文档、SDK 来源、版本及服务发现／意图提交／续接／查询／取消的接口契约。
- 应用注册、证书、用户授权、签名、防重放及任务结果回传规则。
- 可用服务目录、测试环境、限额、收费与上线条件。

拿到正式契约之前不创建猜测的 API、不声明兼容，也不以支付 SDK 替代阿宝执行接入。
