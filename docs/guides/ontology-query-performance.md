# 本体查询性能基准

在仓库根目录运行：

```sh
node --import tsx examples/ontology-query-benchmark.ts > /absolute/local/archive/ontology-query.json
```

输出目录须先存在；测量报告放在仓库外。`--samples=25` 控制每项预热后的样本数，`--sizes=1,5,10,25,50,51,100,500` 控制报名观察历史数量。固定时钟、来源合同和数据形状；不加载凭据或调用外部服务。重复比较时保持 Node 版本、机器负载、参数及数据库模式一致。输出记录 Git SHA 和工作区是否存在未提交改动。

## 测量范围

| 场景 | 用途 |
| --- | --- |
| 按已知引用选取字段 | 检查历史增长是否导致无关关系扫描 |
| 读取一页历史引用 | 观察分页查询的语句数量及实际返回 SQL 行数 |
| 校验当前报名条件 | 包含来源证明、关系完整性及历史取代检查；未知结果仍记录为未知 |
| 四项独立事实与同批事实 | 比较相同字段需求的图查询合并、SQL 次数及响应字节数 |
| Foundation 累积证据读取 | 使用权限回归同一夹具，分别测量 1、8、32、64 个输入依赖；每次重新进入任务授权范围 |

每项记录首次调用，以及预热三次后的本机中位数和第 95 百分位耗时；首次调用位于模型编译与夹具初始化之后，不能视为进程冷启动。SQL 计数覆盖同步测量窗口内各连接的 `StatementSync.get/all/run` 执行入口，测量前准备的语句与重复执行同一语句也计入；不以 prepare 次数代替执行次数，也不反复包装语句实例。窗口结束或抛错时恢复方法，嵌套窗口分别计数。图查询、对象读取、关系读取和评估分别计数，层级会重叠，不相加为总调用量。SQL 行数是这些语句返回给 JavaScript 的行数，不是 SQLite 内部扫描行数。

计数器与结果序列化会增加测量开销。可信内部读取使用隔离内存 SQLite；Foundation 使用隔离磁盘数据库，同时计入任务、成员身份、字段与证据依赖检查。两类结果分开报告，不直接比较绝对耗时。初始化、夹具接入、模型推理、供应商网络及生产竞争负载均不在范围内；模型和供应商调用次数均为零。这些本机数据不构成生产 P95、模型 token、完成率或服务 SLA。

## 读取完整性与优化约束

`query()` 返回明确分页与 continuation，应用可按需继续读取；缺少当前字段和本地分页不能一律触发供应商重查。已知引用优先直接选取字段；同一同步读取可合并事实需求，后续决策仍复核权限和版本。

关系分页按关系目标的 `(type,id)` 索引键推进游标，联表前最多取 201 个候选，其中第 201 个用于判断后续页；每页最多处理 200 个。可信内部读取遇到删除或悬空目标时，空页仍可带 continuation。授权读取从当次已经验证的任务对象边界做精确关系查找，不用隐藏关系的数量产生额外分页；仍逐对象检查版本和字段投影。调用方须以 `hasMore` 判断是否读完，不能以 `items.length === 0` 判断。

固定定义的校验独立于结果分页：使用端点／定义摘要复合索引，逐个定位不同的摘要，仍核对整个关系集合，包括页外、不可见和悬空边；超过 200 种定义拒绝读取。旧库在正式存储初始化时幂等补建正反向索引，普通只读视图不迁移数据库。新增索引会占用磁盘并产生一次性建立成本，测量时应将它与初始化后的读取耗时分列。

每个对象存储只复用正反向至多两条定义查询的编译语句，每次仍绑定当前 ontology、owner、关系类型和端点并执行查询；不复用定义行、对象、权限或验收结果。新的 SQL 准备成本与 SQL 执行次数须区分：编译复用可降低延迟，但不能据此报告查询量下降。

内部 `related()` 用于需要完整邻居集合的计算和写入。达到数量、响应字节限制，或者授权过滤使集合不完整时，抛出不含隐藏对象标识或数量的冲突。函数评估、派生属性与条件评估保留 unknown，普通已读字段仍可返回；硬条件未知时不能通过执行检查。写入不能以空列表继续。完整且确实为空的集合仍返回空列表。该行为也约束历史观察取代、依赖匹配与关系替换；不要用 `?? []` 或捕获后返回空数组恢复旧语义。

历史集合过大时，应保留未知并报告边界。后续优化应基于准确来源身份、当前版本或受信索引定位需要核查的观察，同时证明未遗漏较新／冲突状态、跨账号隔离和历史解释。不能通过无界遍历、提高模型轮数、删掉完整性检查或跨决策复用授权来取得更好数字。

回归入口：`tests/ontology-relationship-pagination.test.ts`、`tests/relationship-completeness.test.ts`、`tests/security-data-policy.test.ts`、`tests/ontology-query-benchmark.test.ts` 和 `tests/security-read-dependencies.test.ts`。基准本身无墙钟性能门槛，避免把机器负载波动变成 CI 失败；回归检查的是实际计数、合并行为和不完整读取的拒绝。
