# 跨 Ontology 对象复制

定义迁移完成并发布目标类型后，`OntologyPackages.migrateData` 可以复制当前身份拥有的对象与关系。来源和目标都必须已经存在并处于活动发布。输入包含 `sourceOntology`、`targetOntology`、`requestId`、显式类型映射 `types` 和关系映射 `links`。可通过 `objects` 指定对象引用，省略时选择已映射来源类型下当前 owner 的全部对象，最多 10000 个。

调用者须具有两端的定义与实例读取权限，以及每个目标类型的独立 `migrate_objects` 授权，例如 `Consumer/object/ImportedItem`。普通成员授权不包含该权限。来源中存在不可读取的行或字段时，整个复制失败。目标对象执行其当前 Schema 和安全策略，已有目标 ID、映射身份冲突、关系端点不完整和基数冲突均使事务回滚。

属性按同名字段复制，主键属性可以随目标类型的主键名称调整。来源与目标的派生字段由各自查询计算，不写入存储。其他字段必须能通过目标 Schema。带有显式映射且关联选中对象的关系，需要两端对象都在复制选择中。`OntologyScenario` 等生命周期元数据禁止跨本体复制。

来源读取、目标创建、关系写入、编辑历史和迁移凭据共用事务。两端发布与 owner 写锁按固定顺序取得，因此复制过程中不会切换发布或混入同一 owner 的并发业务更新。目标对象与关系被复制，来源数据保留。

每次成功复制保存来源和目标的发布 ID，以及每个对象的来源引用、版本、内容摘要和目标引用。关系审计保存原关系与映射后关系。`migrationReceipt` 使用 `{id,kind,after,limit}` 读取分页凭据，其中 `kind` 为 `objects` 或 `links`。凭据读取和相同 requestId 的重试都会重新检查当前权限。相同请求返回既有凭据，改变参数的重复请求会被拒绝。

数据库升级调用 `initializeOntologyDataMigrations`。迁移执行身份需要三个迁移审计表的 SELECT/INSERT，以及现有对象、关系、来源状态和编辑历史的必要权限。迁移行为不发起外部系统调用。
