# 仓库结构与维护

`main` 是集成主线。专题开发使用短期 `codex/` 分支；完成验证后合入主线。清理分支前检查其提交已完整进入保留分支、当前远端 SHA 未变化，并保存恢复记录。其他工作区的在途改动保留。

| 位置 | 职责 |
| --- | --- |
| `apps/gateway/` | MCP、A2A、认证、会员、本体管理及网络入口 |
| `apps/worker/` | 持久领取、模型调用、执行、恢复和独立验收 |
| `apps/relay/`、`packages/relay/` | 独立加密通信入口与专属信箱存储，不读取业务库或启动执行器 |
| `packages/agent-transport/` | 节点身份、标准加密封装、持久收发与宿主接线 |
| `apps/provider-mcp/` | 美团供应商协议适配；不另建业务本体 |
| `apps/participant-browser/` | 免费报名的本机浏览器操作队列 |
| `apps/*-sandbox/` | 独立的合成服务提供方 |
| `packages/ontology/` | 本体定义、注册库、编译、对象与关系、函数及版本兼容 |
| `packages/ontology/definitions/` | 唯一可编辑的供应商 MCP 绑定数据 |
| `packages/core/` | 任务、授权、账本、存储和来源身份 |
| `packages/coordinator/` | 基于同一任务本体的规划和多服务执行 |
| `packages/capabilities/` | 业务程序、供应商连接器和验收器 |
| `packages/members/`、`packages/network/` | 会员身份和有权限约束的协作网络 |
| `packages/agent-client/`、`integrations/` | PA 客户端与外部协议适配 |
| `packages/deployment/`、`scripts/` | 构建、配置、依赖和部署工具 |
| `tests/`、`examples/` | 自动回归、合成夹具和可复用调用示例 |
| `docs/`、`pitch/` | 当前指南与产品演示页面 |

## 文件归属

源码、依赖锁、合成测试夹具、当前指南和可复用演示纳入 Git。内部计划、阶段记录、真实账号联调证据、截图及原始命令输出留在本地归档。凭据、配置、数据库、缓存和构建产物进入忽略目录。

整理已有文件时，先复制并核对哈希，再移出跟踪，同时更新实际引用。测试确实依赖的输入提取到夹具中；运行时版本兼容所需的本体历史快照继续保留。移出当前文件列表不等于改写 Git 历史。

## 交付检查

按照项目规则完成类型检查、测试、构建和差异检查，再同步分支并等待对应提交的 CI。整合后的代码、部署版本和真实业务结果分别验收。不要用历史日志、任务完成状态或测试替身证明实际交易与履约。
