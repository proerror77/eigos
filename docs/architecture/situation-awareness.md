# 态势感知与持续履约的设计约束

状态：有界 Pipeline 观察和受影响组件输入检查已有实现，具体启用合同见[Ontology Pipeline](../guides/ontology-pipeline.md#有界来源观察)。完整持续履约修复仍是设计约束。原始设计来自提交 `99731b9`，阶段计划和验收矩阵保存于仓库外；没有合入其他工作区的日历执行器，也不声明真实来源接入或部署完成。

## 目标与分工

持续目标是在用户明确委托的观察期限内，接收现实变化、判断对原目标及已选计划的影响，仅修复受影响部分，再按当前证据和权限验收。一次性报名等任务完成后，不自动创建长期观察；另行委托守护时创建关联任务，原 completed Task 不重开。

Gateway 验证身份、接收获准变化、持久化并返回安全投影，不启动模型或轮询。Connector 只做一次来源操作，声明推送／查询／游标／原生版本和在线操作代理条件。Worker 复用当前 SQLite 领取与持久调度，不新增常驻 Guardian 模型或第二套执行系统。Ontology 定义和映射仍固定于同一不可变发布；变化更新实例事实，而非让模型重造 schema。

没有相关变化的巡检不调用模型；只有补证、选择替代方案或澄清业务选择才进入决策。模型选择动作，确定性代码负责时间、版本、防重、失效和权限检查。

## 拟议合同

| 合同 | 必须保留的语义 |
| --- | --- |
| SourceChange | owner／账号／来源绑定、原生对象身份与映射版本；事件 ID、防重摘要、原生排序范围、occurredAt／observedAt／receivedAt、受控载荷及处理回执 |
| ObservationWatch | 明确字段与条件、起止时间、终点证据、失鲜上限、已选读取动作、输入和来源、推送／轮询策略、累计成本、授权与撤销版本 |
| 组件代次与结果有效性 | request revision、事实版本、组件代次、计划版本和证据修订分开；历史结果不删除，当前结果标记 valid／stale／superseded |
| SituationAssessment | 当前事实对原目标的意义、受影响组件／条件、证据、评估时间和不确定性；不替代历史 OutcomeAssessment，也不把预测当履约事实 |

表中名称描述领域语义；当前观察采用 PipelineWatch 和内部调度记录，没有新增共享业务类型或 SituationAssessment。来源同键同内容返回原记录；同键异内容保存冲突并阻止依赖，不把最后到达的值自动当真。没有供应商版本时保持 unknown，不能用本地 attempt ordinal 或接收时间伪造外部顺序。提示性通知必须经权威回读才能采纳。

收件、事实采纳、依赖失效、任务唤醒和处理回执需要可恢复的事务边界。无变化读取不生成新的语义事实版本或成功样本；过期事实重新变为可用则必须重新计算条件。断流、休眠、离线或操作代理缺失必须显示 stale／unavailable／operator_required，不能继续声称有效监控。

## 修复与授权

事实变化和单纯到期都可使计划／结果失效。保存消费字段、语义值摘要、关系及新鲜度依据，只修复受影响的输入和组件；无法证明无关时保持待评估。已完成组件只可开放明确的观察动作，不能整体解除完成保护并重放业务写入。

每次修复固定原组件代次、触发变化、依赖版本及替代计划；目标、输入或图的语义改变时重新核查覆盖。变更程序或提供者需新的版本化图与当前授权，不能静默替换。派发前和主目标验收前都检查待处理变化与版本；已开始外部调用不能当作本地事务回滚，必须保留原操作查证。

观察许可不等于改约、日历写入、取消、下单或付款。第一阶段继续使用准确 planDigest 许可；任务级自动调整预授权属于后续独立合同，模型不能给自己签发子许可。未知业务效果和支出不能通过新组件代次或新任务重试，退款也不自动变为新预算。

持续任务区分守护期限、单次活跃执行时限和生命周期累计预算。唤醒、修复、重启不能清零预算。到期不是到场或履约证明；缺乏终点证据时保留部分结果与 unknown／未满足原因。

## 活动改址示例与验收边界

活动场次的稳定来源身份、时间、地点和事实版本关联原报名、原日历事项及交通路线。活动改址后，应读取原报名是否仍有效，使旧日历地点及旧报价失效，模型选择修改原日历事项并查询新路线，再分别独立回读原日历 ID 与当前场次版本。

地点必须来自已验证的结构化来源，不能由标题猜测。日历未接入时返回 unsupported，`.ics` 或文档不能冒充已写入账号。缺入场截止、接驾等待或路程时间时，最晚出发时间保持 unknown；滴滴价格不能推导到达承诺。报价、接单和实际到达分别验收。

后续实现至少验证：重复／乱序／冲突事件；无原生版本；收件与唤醒之间崩溃；断流与失鲜；自然过期；局部改址；计划产生后再次变化；取消／撤权和迟到通知；未知写入与预算；跨 owner 隔离；缺来源／时间；长周期预算；验收与新变化竞争；部分成功；重启后两协议同任务回读。首轮用合成来源验证合同，真实来源读取、日历写入和真实履约分别按授权取证，不能据此宣称生产实时性或 P95。
