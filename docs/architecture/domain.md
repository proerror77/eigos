# EIGOS 服务委托领域术语

EIGOS 协调用户授权的现实服务，连接用户的 Personal Agent 与实际服务提供者，并根据证据核对结果。这里的术语用于描述业务，不代表相关服务已经接通。

## 参与者与需求

**用户（User）**：提出目标、拥有偏好并授予业务操作权限的人或组织。

**Personal Agent（PA）**：代表用户沟通目标、背景及已有授权的个人助手；它的推测不等同于用户确认。

**服务需求（ServiceRequest）**：一次用户目标及其约束、交付边界和当前已知信息。例如“生成咖啡待付款订单”和“把咖啡送达”是不同交付边界。
_Avoid_：用“订单”指代尚未明确的需求。

**偏好事实（PreferenceFact）**：有来源和适用范围的用户选择倾向，例如咖啡口味。偏好不自动构成当前操作授权。

**约束（Constraint）**：本次服务必须满足的条件；需区别不可违反的条件与允许协商的偏好。

## 服务与方案

**服务提供者（Provider）**：提供业务能力的主体，需标明渠道、实际商家和履约方等角色；同一需求可以询问多个提供者。

**服务渠道（Channel）**：可用于查找或委托服务的入口，可能聚合多个商家；一个渠道能搜索商品不代表它也支持为当前用户下单。

**商家（Merchant）**：具体售卖商品或接受预订的业务主体；渠道名称不一定是商家名称。

**服务能力（ServiceCapability）**：可委托的业务结果及其输入、适用条件和验收含义。同一种能力可以由多个提供者实现，能力声明与当前任务可执行性分别判断。

**候选项（CandidateOption）**：可供选择的商品、服务方案、门店或时段；候选项不代表已经锁定资源或获得提供者承诺。

**服务报价（Offer）**：提供者通过某渠道，在特定条件下针对商品或服务给出的价格与条款。在本体中以共用接口表达，配送报价、商品报价和预订报价是各自的具体对象类型。
_Avoid_：把商品标价直接称为最终实付总价。

**比较结果（Comparison）**：针对同一需求、按照明确条件对可比候选作出的比较记录，包含已查询范围、未完成查询和不确定信息。
_Avoid_：将部分渠道中的较优结果称为全网最优。

**确认方案（Proposal）**：供用户确认的具体服务安排、费用和条款快照。方案变化可能影响已有授权是否仍适用。

**成功条件（SuccessCriterion）**：用户约定的业务结果必须满足的条件。例如取得运费报价、收到指定商品、获得预订确认分别需要不同证据。

**搜索范围（SearchScope）**：本次查找对象所使用的地域、关键词及其他限制。它不构成服务可达范围或配送目的地的证明。

**服务目的地（ServiceDestination）**：本次业务实际需要交付到的位置，与用于发现候选的搜索范围分别表达。

**业务授权（Authorization）**：用户或其有效代理对明确动作、对象、范围和条件的许可。
_Avoid_：把已连接账户、已读消息或模型判断称为业务授权。

## 执行与结果

**委托会话（ServiceEngagement）**：EIGOS 与一个服务提供者围绕某项需求开展的持续沟通和处理记录；同一需求可同时存在多个询价会话。

**执行尝试（ExecutionAttempt）**：发起某个业务动作的一次尝试；没有收到结果不证明动作未发生。

**执行计划（ExecutionPlan）**：某次决策形成的版本化动作安排，固定输入和依赖；不同于报价选择的业务方案，也不自动产生授权。

**执行步骤（ExecutionStep）**：计划中的一个调用意图，关联动作定义、实现绑定、输入、前置步骤及实际尝试。步骤运行状态与业务目标完成分别判定。

**执行结果（ExecutionResult）**：一次尝试收到的记录，明确是否通过验证、是否被当前任务接纳，以及对应的业务观察。迟到回执可以保留，但不因此更新当前结果。

**商品订单（Order）**：供应商确认建立的商品交易记录。待付款、已付款与已交付是不同事实。

**餐厅预订（Reservation）**：针对特定餐厅、时间与人数的服务安排及其申请、占位、确认等状态。只有取得餐厅或授权渠道确认并满足生效条件，才能称为已订妥。
_Avoid_：将排队号、团购券或推荐列表称为已确认的餐厅预订。

**预订时段（ReservationSlot）**：餐厅在指定日期时间、人数及条件下提供的候选预订选项。可查到时段不代表已占位或已确认预订。

**占位（Hold）**：提供者在明确期限和条件下暂时保留资源的业务状态。到期或未满足条件可能失效，不自动等同于已确认预订。

**业务观察（Observation）**：来源在某个时刻返回的状态或信息，需核对对象、来源和含义后才能用于判断事实。

**业务事实（Fact）**：对业务对象某项属性或关系的明确陈述，附来源、证据、时间和适用范围。未证实推断、缺失值与冲突信息保留各自状态。

**证据（Evidence）**：能够说明某项业务事实的来源记录，如供应商订单回执或预订确认。

**供应方估计（ProviderEstimate）**：提供者对费用、时间或其他结果的预测，带假设和适用范围。

**供应方承诺（ProviderCommitment）**：提供者明确承担的业务条件，带适用对象、期限与条款；最终是否兑现仍需观察实际结果。

**结果核验（OutcomeAssessment）**：将实际证据与用户约定的交付条件比较后得到的结论；证据不足时不推定成功。


## 能力发现与受控执行

**能力声明（CapabilityClaim）**：提供者或目录关于某项服务能力的陈述，带来源与适用范围；被发现不代表已经核验。

**能力验证（CapabilityVerification）**：针对具体动作、条件和时间范围的验证记录。格式验证、模拟验证与真实履约验证证明不同事情。

**本次可用性（RuntimeAvailability）**：某项能力对当前需求、用户和时间是否可用的观察；历史成功不保证本次有库存、产能或时段。

**动作类型（ActionType）**：用户或 Agent 的业务决策所触发的一组受控对象、属性或关系变更，包含提交条件与规定副作用，例如选择报价、请求预订、申请退款。
_Avoid_：把供应商端点或协议方法直接当成跨服务统一业务语义。

**提供者绑定（ProviderBinding）**：一项业务能力由哪个渠道和服务主体提供，以及如何对应其实际执行方式的约定。

**动作意图（ActionIntent）**：针对确定业务对象的一项获准操作的持续记录；同一意图可有多次查询或技术尝试，不能因此重复产生订单。

**售后事项（AfterSalesCase）**：关联既有订单或服务的后续请求及处理记录，例如补交、退换或退款；申请受理和最终解决分别记录。

**能力图谱（CapabilityGraph）**：任务、能力、提供者、业务动作和履约证据之间的可追溯关联；它不是对全部提供者能力的无条件背书。

## 本体建模术语

**对象类型（Object Type）**：一种有明确业务身份的实体或事件的定义；具体某笔订单或某次交付事件是对象实例。

**实体（Entity）**：本项目中指具有稳定身份的领域对象或规格记录，不等同于 BFO 的“物质实体”。例如 `ProductVariant` 是来源限定的商品变体／规格身份，并非一件有序列号的实物。价格、Token 或查询任务变化不应使同一规格变成新身份；无需为这些对象另加通用 Entity 表。

**来源观察（Source Observation）**：来源在明确时间和版本对实体作出的陈述。当前实体可引用最新有效观察，历史决策保留当时的观察；不能把来源原生 ID 未经核验地合并为跨来源身份。

**关系类型（Link Type）**：业务对象之间有明确含义、两侧名称和基数的关系定义，支持从两侧理解和导航。

**接口（Interface）**：若干具体对象类型共同具备的业务属性、关系或行为约定；接口自身不充当某次业务实例。


**对象集（Object Set）**：在获准范围内按明确条件得到的一组业务对象，例如当前需求的有效报价。

**本体函数（Function）**：应用中基于业务对象、关系和规则运行的只读计算，例如比较报价或计算未交付数量。这里的程序 Function 不对应 BFO 的功能类别；受控业务动作继续独立表达。


## 领域属性与来源身份

**商品属性档案（ProductAttributeProfile）**：按电子商品、服装、包装商品或通用商品约束字段与单位的 Data Schema。来源明确声明的属性与用户要求分别保存；旧标题和自由文字规格不能直接当成严格匹配证据。

**来源身份断言（EntityIdentityAssertion）**：一条带确认主体、依据、来源版本、有效期和撤销历史的跨来源身份关系。可表达相同、不同、未知和冲突；不合并对象 ID，不共用价格、库存、政策或操作许可。

**酒店套餐（HotelRatePlan）**：同一酒店和房型下的一组早餐、儿童、付款和取消条款。酒店相同不代表套餐相同；房型、库存和固定报价各有自己的来源观察。

**派车分配（TransportAssignment）**：供应方对一次乘车/接送结果分配的司机和实际车辆，独立于预先报价使用的车型。保留历史分配，抵达上车点、上车、送达及最终费用分别核验。

**交易参与角色（TransactionPartyRole）**：绑定准确报价、订单、包裹或路线版本的销售、履约、承运或收发角色。复用 Provider、ChannelParticipation 和已选 SavedAddress；地址只证明选定联系端点，不认证自然人身份。

**跑腿服务类型（ErrandServiceType）**：寄件配送、代买配送、代排队/提交是不同业务约定。当前只有寄件报价的只读绑定；类型定义不产生代买、排队或真实履约能力。



## 通用本体参考与指称

通用语义参考不等于正式类公理对齐、RDF 导出或推理机验证。领域对象与运行账本使用当前注册类型及身份。

- 每类先说明它指称现实主体、来源限定规格、计划、状态陈述还是证据记录。保存一条数据库记录不证明相应现实过程已经发生。
- `TransportDriver` 表示来源限定的驾驶人引用；驾驶角色与 `TransportAssignment` 派车分配记录分开。`TransactionPartyRole` 是准确范围内角色分配的证据记录，所选收发地址不等同于本人身份。
- `*Observation`、`SourceReceipt`、`ExecutionAttempt`、`ExecutionResult` 在此表示记录；实际观测、调用或履约过程是这些记录描述的对象。调用过程与供应方履约过程也分别判断。
- 来源规格、申报值、实际测量和用户要求分别标明。目录属性、角色分配、能力声明和逻辑一致性均不能单独证明真实履约。
- 读取一条关系只覆盖该关系。没有读到准确交易角色，不代表不存在渠道参与者；没有调查的范围应保留未核实，不能表述为全图缺失。

## 定义与执行版本

**本体命名空间（Ontology）**：拥有独立定义版本与实例范围的业务模型容器；命名空间不替代对象 owner 或来源授权。

**定义资源（Definition Resource）**：Object Type、Link Type、Interface 或 Action Type 的稳定资源身份；API 名称发布后不复用，显示信息可独立演进。

**本体发布（Ontology Release）**：四类定义和准确校验／处理器引用组成的不可变快照。激活决定新任务采用的版本，在途任务保持原版本。

**受管数据动作（Managed Data Action）**：以 `object_write` 效果改变用户可管理的对象或关系，经过准确预览、授权、Worker 提交和回读；不会自动产生订单、付款或供应商履约事实。

管理入口、兼容策略和验证见[动态本体实现](../guides/ontology-modeling.md)。


## 来源可复用实体与业务事实

**实体身份**：在明确的来源与 owner 范围内指向同一个业务对象。查询次数、任务 ID 和价格变化不改变酒店或供应商身份。来源没有稳定原生 ID 时，只能复用明确标注的同内容地点，不能凭同名或邻近坐标判断现实同一性。

**车型费用估计（RideEstimate）**：针对确定路线与车型的一次来源费用估计，带币种、观察时间和有效窗口；不等同于最终车费或接送承诺。

**酒店参考价格（HotelPrice）**：针对确定酒店及入住日期、晚数和人数的来源参考价格。来源没有说明时，按晚／全程口径、房型、库存和税费保持未知。

**活动或预约场次（Event）**：由来源的规范服务地址标识的活动及其时间信息；缺失的场地和参与资格不能推定。

**参与者报名（EventRegistration）**：来源、活动和参与者限定的稳定报名记录；提交、审核、候补和确认分别表达，实际参与者不能自动等同于委托账户。

**结账商品明细（CheckoutItem）**：一次来源观察中的商品规格引用、数量和单价。保留规格版本，未付款结账明细不是订单行。
