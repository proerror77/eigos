# 任务目标、编排与验收

统一运行时使用同一已发布本体、任务 revision、动作账本与许可。模型提出目标解释、来源读取、动作和完成依据；主机独立校验，提案本身不执行或授权。

## 目标覆盖

任务说明的完成不能替代真实业务目标。单能力解释核对原始消息、输入、约束、条件和所选能力，保存 GoalCoverage 及实际模型响应引用。固定封闭输入且 PA 明确指定能力时，可在一轮模型响应中核对已注册范围并选择首轮只读图；单消息可使用完整原文引用编码，保留 wire 与还原后摘要。多轮局部纠正继续逐段核查，不能为提速省略约束。

原生多服务路径先固定整个 GoalContract，再发现精确 action binding、准备组件上下文并选择跨服务动作。`services.compose.live`／`services.compose.sandbox` 的显式组件图保留各自的类型化交接、依赖与共享预算合同。两种编排都必须满足全部主目标；一个组件成功不能替代其余组件，父级许可也不授权子来源。

## Action 与证据

同一读取图可以绑定前一步真实接受的对象，并执行本体声明的纯函数；未知或有歧义的结果返回决策，不猜引用或自动运行依赖。受管对象写入和供应商业务效果各有准确许可，不能互相代替。包含业务效果的图至多一个写动作；供应商写操作不通过未来值获得隐式授权。

明确声明 planned completion 的来源允许模型预选未来验收对象。创建官方 Mock 订单后，只有明确允许的沙箱回查能接收实际原订单对象并做条件验收；主机仍重新读取、检查来源、当前权限和硬条件。真实写入不因这个扩展被启用。

## 结果与反馈

来源动作保留 Intent、Attempt、Observation；结果验收与 ExecutionFeedback 在同一受保护写回中更新。完成、未知、未满足、需人工与取消分别表达。模型判断、模拟结果、已创建订单和真实履约不是同一证据等级。

历史完成不刷新供应商事实或授权。迟到结果只能追加审计，不能覆盖取消／撤销／改版。未知业务操作只能按原身份查证，不允许通过新任务或新来源重做。

持续观察、组件代次和局部履约修复仍为[态势感知设计合同](situation-awareness.md)，不能把当前一次性任务完成扩展为长期监控承诺。
