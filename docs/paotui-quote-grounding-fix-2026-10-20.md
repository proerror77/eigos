# 文件查价的需求解释修复

真实 PA 查价验证中，用户补充了一个文件、500克上限和普通送。执行侧在需求解释校验阶段终止，尚未发出地址详情或费用预览。隔离重现同一请求时，实际模型将“送一个文件”抽取为 `quantity=1 / 份文件`，被精确来源引用校验拒绝。

## 修正

跑腿报价的标量数量是计价重量；一个／一份文件等件数是用户声明的物品内容，不是实际交付件数要求。解释说明明确保留这些内容，并按整数数量契约使用克表示小于一公斤的质量。执行 Agent 的说明要求尽可能在 `goodsName` 保留用户明确给出的件数描述，不据此声称物品已被称重或交付。

解释的 schema、引用或数值不匹配时，协调器保存不含供应商私有数据的校验反馈，在原请求版本内让模型纠正。仍独立校验原文、固定条件与能力范围，没有程序代替模型选接口或更改用户事实。相同校验问题三次后停止；已用模型轮次和原有执行预算保留。

能力越权、来源授权、归属、存储错误、取消和租约失效继续沿原有拒绝／交接路径处理。来源调用之前的反馈不能替换已经可执行的计划或 Agent 状态。Agent 范围初始化因输入格式失败时，范围与尚未接受的需求一并回滚。

## 验证

- 实际模型隔离复现修复前的件数／重量错误；修复后同一请求正确产生500克计价要求及普通送的报价适用性条件，输入仍为空对象。诊断没有调用供应商。
- 新增四项回归：原任务中反馈纠错且零来源调用、三次相同错误停止、范围初始化回滚、取消后的迟到解释不可写回。
- 全部479项测试、9项进程级 E2E、类型检查、构建、差异检查通过。
- 原有禁止虚构能力、指定来源不可切换、非沙箱任务不可使用沙箱、取消保护的测试继续通过。

验证驱动也改用既有 SDK 在长时间原生 PA 运行前刷新快到期的访问令牌。先前固定 Bearer 在人机交互等待后过期，被网关正确拒绝；未放宽登录绑定，也未重放已接受的写请求。

以上是输入解释修复证据，本身不能证明真实报价完成。旧版本失败任务保留原状态、模型回执和读取历史；恢复原只读请求时须单独核对所有者、请求版本、无当前执行计划和无待定业务副作用，并记录恢复事件。来源凭据期限和新鲜地址校验继续生效。

后续结果：修复代码的[精确提交 CI](https://github.com/proerror77/eigos/actions/runs/39283433578)已成功，私有实例已核对至该版本。原失败任务按上述条件恢复后，继续补问并发生来源续期；预算不足时由 PA 取消并保留记录。真实费用预览最终在一个明确关联的后续任务完成，见[独立查价证据](evidence/member-quote-live-2026-10-20/README.md)。该后续证据与修复本身分开，不将原失败记录改写为成功。
